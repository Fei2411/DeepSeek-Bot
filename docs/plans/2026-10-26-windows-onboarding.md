## 为什么

### 谁在用

Windows 是桌面应用的主要平台：0.2.0 到 0.2.2 三个版本的安装包下载里，Windows 约 3850 次，macOS 约 1900 次，Linux 约 250 次（GitHub 下载计数，含自动更新）。这些 Windows 用户几乎不提 Issue：259 个 Issue 里能确认来自 Windows 桌面应用的只有 3 个左右。另一边，有 10 位不同的用户报告过「第一条消息就失败 / 没有回复」。大多数人是在半路悄悄放弃的。

典型用户：中文界面，可能不是开发者，可能在中国大陆（GitHub 慢或打不开），可能还没有 DeepSeek 账号或 API Key，可能从没用过 DeepSeek Harness（DSH）。

### 今天的路有多长

2026-10-26 在 `dev` 上用全新用户的身份实测：一次性的家目录、数据位置和壳数据，环境里没有任何 key，界面中文。实测用的是未打包的 Electron 和 `DS_BOT_HOME`，所以下表的下载、安装、首次启动对话框、导入、启动失败和卸载几行来自代码、CI 和用户报告，其余几行是实测。

| 步骤 | 用户看到的 | 问题 |
|---|---|---|
| 下载 | README 先是英文；Releases 页是英文更新日志加 11 个文件，按字母排，`.exe` 排第五，紧挨着 `.exe.blockmap` | 不知道下哪个；约 212 MB 只能从 GitHub 下，没有国内镜像 |

| 安装 | NSIS 向导：选目录（点「安装」）→ 进度 → 完成（点「完成」） | 多两次点击，NSIS 默认图 |

| 进入窗口 | DSH 的「预览版说明」（讲 DeepSeek Harness 0.2、开发者、插件 API）→ DSH 的「开始使用」（登录 / 添加 API Key）→ DSH 的「添加一个 API Key 开始使用」；下面 Chief 的卡片又问一遍「我还没有可用的模型。你想怎么配置？」 | 四个面，两个重复。没有一个告诉用户 key 去哪里拿、要先充值、填的 key 对不对 |
| 先打字 | 红字「本轮运行失败」加英文原文 `llm-deepseek: no API key for provider route "deepseek-official"; … export DEEPSEEK_API_KEY in the launching environment`，代码 `MISSING_CREDENTIAL` | 中文界面里的开发者报错，没有按钮；这条消息还会删掉 Chief 留着的开场白 |
| 填了 key 之后 | Chief 再问一次「先给我选一个模型吧」，选完才打招呼 | key 从不校验：填错或余额为零，要到第一轮才报「API 密钥无效」或「额度已用尽」，只有文字，没有按钮 |
| 第一个小时 | 默认沙盒下 Bot 跑的每条命令都可能返回 `exit code 3221225794`（#523）；Host 不读 Windows 系统代理，Clash、v2rayN 只开系统代理时请求不走代理（#529 的「连不上 GitHub」很可能是这个原因，推断）；冷启动可能一个 Bot 都不显示（#559）；导入后第一条消息可能 84 秒没有任何显示（#384） | 都没有说明和下一步 |

另外，「下载」文件夹解析不到时（被删掉，或者重定向到一个当前不可用的位置），`app.getPath('downloads')`（`main.mjs` 建窗口时调用）会抛错：窗口一直不显示，等最多 15 秒后弹出「DeepSeek Bot 没能启动」和 Electron 的英文报错，然后退出。已在 Electron 44 上复现这个抛错。

手里已经有 key、也没有 DSH 团队时，最快也要：两次 SmartScreen 点击，安装向导点两次，一个系统对话框，等 13 到 21 秒，再点「继续 → 添加 API Key → 粘贴 → 保存并继续 → 选模型」，一共 10 步，第一条回复才出来；有 DSH 团队时最多 13 步。没有 key 时还得自己离开应用去弄一个。

### 根因

1. **首次启动按实现来提问。** 数据位置、总工作区、DSH 的 profile 都是实现概念，却在还没有窗口的系统对话框里先问用户。
2. **接模型有三个入口，彼此重复，又都不完整。** DSH 网页版自己的两步引导，加上 Chief 的卡片。哪个都不说怎么拿 key、要付费、key 能不能用。
3. **失败不给下一步。** 凭据错误显示原文，启动失败弹英文框，导入遇到新版对话是死路，导入只给一次机会。
4. **分发只靠 GitHub，而且没签名。** 下载和自动更新都走 GitHub，SmartScreen 和智能应用控制把人挡在门外，发布页不告诉人下哪个文件。
5. **第一个小时的坑没人接。** Windows 特有的沙盒启动失败、系统代理、「下载」文件夹，以及各平台都有的冷启动不显示 Bot（#559，报在 Windows 上）和导入后漫长的换段（#384）。

### 取舍

- **每个阶段只有一个引导面，显示什么由状态决定，不存「已完成」标记。** 引擎起来之前，引导面是应用自己画的启动页；引擎起来以后，是 Main Bot 聊天里的设置卡。跳过的步骤哪里都不记，条件还在，它下次就自己回来。第 6 节的上手也不另存标记：Main Bot 的会话里有那行「上手结束」的灰字、或者有用户自己发的消息，就算结束；「跳过设置，直接开始」写下的那行灰字是它唯一的记录（第 8 节）。
- **模型在聊天卡里接，不在应用里另做欢迎向导。** 设置卡是插件的代码，DSH Desktop 和 DSH Web 里的用户也一起受益；应用里再做一套向导，就要维护两套。启动页只负责让人看见它在动、知道下一步是什么：鲸鱼游到哪一站就是到了哪一步，一次只说一句话，好让等待不是空等。
- **模型从「已接上」之后才开始帮忙。** 顺序倒不过来：Key 由引擎写进它自己的 `DSH_HOME`，DeepSeek 登录的回调也由引擎的 Host 处理，所以引擎必须先在某个数据位置上跑起来；`importTeam` 遇到已有 Bot 的位置直接拒绝，复制时还整个换掉 `bot/` 并重启引擎，先填的 Key 也会压过导入来的 Key 和登录。所以位置、导入、接模型三步保持卡片。模型只在两处比卡片好：把用户的一句话变成有名字、有角色的 Bot，以及自由的第一件事；它也更慢、先花钱、措辞每次不一样，所以每一步都留一张不靠模型也能走通的卡，限制写成代码里的机制，不写成提示词（第 6 节）。
- **先补悄悄流失的地方。** 下载页、信任提示、一键安装最便宜，影响面最大。签名和国内镜像要等外部审批和账号，所以最先开始办。
- **不改 DSH。** 只用有文档的开关和插槽。DSH 的「预览版说明」没有文档开关，就向 DSH 提需求，期间在启动页上先提醒一句；不伪装 `dshDesktop`。

## 已定的行为

下面写的是新流程。界面文字的源语言照旧：插件是英文加 `i18n.js` 里的中文，应用主进程用自己的中英文表；这里只列中文。文案里的 `{名字}` 是 Main Bot 的名字。标了「待定」的几处，按文末「待定」里的建议写，拍板后改成定下的那一种。

### 1. 下载

- `README.md` 和 `README.zh.md` 开头都是同一块中英双语的下载区（GitHub 默认显示英文 README）：Windows 10/11（64 位）、约 212 MB，「国内镜像下载（推荐）」和「GitHub」两个直接下载链接。镜像没验证通过之前只放 GitHub 链接，不放死链。
- 下载区紧接着写清：双击就会安装，装好自动打开；不用管理员权限，不用另装 Node 或 DSH；需要一个 DeepSeek 账号（可以当场用手机号注册）或 DeepSeek API Key；DeepSeek 按用量收费，一轮对话大约多少钱（实测默认模型上三次第一件事的回合得出，附 DeepSeek 价格页链接）；DS Bot 是社区开源项目，不是 DeepSeek 官方产品。
- 签名之前，下载区带一段信任说明（文字加自己画的示意图，不贴 Windows 或其他产品的截图）：
  - Edge 提示「不常下载」：「···」→「保留」→「显示更多」→「仍然保留」。
  - 「Windows 已保护你的电脑」：「更多信息」→「仍要运行」。
  - 「智能应用控制已阻止…」且没有「仍要运行」：未签名的安装包没有安全的绕过办法，请改用 DSH Desktop 加 DS Bot 插件。不要关掉智能应用控制。
  - 杀毒软件拦截：先用 `certutil -hashfile <文件> SHA256` 和 `SHA256SUMS.txt` 核对，再选「信任」。
  - 安装时提示卸载旧版失败：先关掉 DeepSeek Bot；杀毒软件拦了安装包时，按上面的方法核对后选「信任」，再运行一次安装包。
- 每个 Release 的说明开头是 CI 生成的「下载 / Download」表：Windows 排第一（国内镜像、GitHub、大小、「双击安装」），然后是 macOS（Apple 芯片 / Intel）和 Linux（AppImage / deb）；表下注明 `.blockmap`、`latest*.yml`、`ds-bot-*.tgz` 和源代码是给自动更新和插件用的，不用下载。之后才是更新日志。
- Release 附上不带版本号的文件（如 `DeepSeek-Bot-win-x64.exe`）和 `SHA256SUMS.txt`。标为 Latest 的 Release 带上这些文件之前，`releases/latest/download/` 的固定链接会 404，所以 README 先链到 `releases/latest` 页面；固定链接（不经过文件列表）和 M3 的固定链接检查一起上。README 里插件安装那一行也不写具体版本号（今天两份 README 都还写着 `ds-bot-0.2.1.tgz`）。
- 发版顺序是「打包（→ 签名）→ 上传到 GitHub 和镜像 → 写下载表 → npm 发布 → 最后才标为 Latest」，不会再出现 Release 已经是 Latest、安装包几分钟后才到的情况。今天的工作流由 `release: published` 触发，没有公开的 Release 就没有标签，而工作流要靠标签检出代码、并检查它在 `main` 上；npm 的 Trusted Publishing 也绑定在 `release.yml` 上。所以起点是维护者发布时不勾「设为最新」，最后一步由工作流 `gh release edit --latest`；npm 发布留在 `release.yml`。
- 新增「安装问题」Issue 表单：不要求诊断信息（应用都没跑起来），只问系统版本和显示语言（主要是 Windows，macOS 和 Linux 的安装问题也用这张表）、卡在哪一步、对话框的文字或手机拍的照片。

### 2. 安装（一键安装待定）

- 双击后只有一个小窗口「正在安装 DeepSeek Bot，请稍候…」和进度条，约 30 秒，没有页面要点。只装给当前用户，装到 `%LOCALAPPDATA%\Programs\DeepSeek Bot`，不要管理员权限。建桌面和开始菜单快捷方式「DeepSeek Bot」，装完自动打开应用。
- 要换程序位置的用户用 `/D=`（README.md 和 README.zh.md 的进阶说明）；数据和总工作区本来就可以放到别的盘。
- 安装语言 `[en_US, zh_CN]`：中文 Windows 用中文，其他语言用英文（今天其他语言会落到简体中文）。
- 在旧版向导装到自定义目录的基础上一键升级，保留原目录（CI 验证）。
- 签名后（路线待定），发布者显示签名主体；设置 `publisherName`，让 `electron-updater` 校验以后更新包的签名。
- electron-builder 自带的几条 NSIS 报错（卸载旧版失败、解压失败）没有中文，照样显示英文。不在 `installer.nsh` 里重新定义它们：electron-builder 默认把 NSIS 警告当错误，重复定义会让构建失败。中文翻译提给 electron-builder。

### 3. 首次启动：启动页

- 窗口先出来。进程启动约 1 秒内，启动窗口就显示应用自己的本地页（`app/src/start/`）：和现在一样无边框，40 px 的标题带可以拖动，系统按钮在右上角，Windows 11 上用 Mica。启动页在单独的启动窗口里，引擎的页面在隐藏的主窗口里加载（[启动窗口](2026-10-26-start-window.md) 第 1 节，待定）。整个启动期间，卡片和失败页也算，启动窗口都是 720 × 540（工作区矮时 720 × 500）；它只在交接时改一次大小：长成主窗口的矩形，主窗口在同一个矩形上露面（同上第 8 节）。
- **鲸鱼就是进度。** 首次启动没有标题、三站的标记和说明：Main Bot 的鲸鱼（88 px）在水线上从第 1 站游到第 3 站，它停在哪里就是到了哪一步；它离开第 1、2 站时各在原处留下一个细线的圈，第 3 站没有。三个真实阶段照旧是「准备数据文件夹」→「启动本机引擎」→「打开团队」，但只给读屏：一个看不见的列表「启动进度」（`aria-current="step"`），朗读区照旧说「{阶段}：进行中」「{阶段}：已完成」。5 秒起右上方显示「已用 N 秒」，一直留到「进去吧」。布局、圈和鲸鱼的动作在 [启动窗口](2026-10-26-start-window.md) 第 2、3 节。
- **文字都是鲸鱼在说，一次一句短话。** 鲸鱼的话在水线下居中，只占一行，不折行；下面的提示行只说接下来要准备什么（接模型、预览版说明、重装接着用），最多约 22 个字，有卡片时隐藏。首次启动的话和提示：

| 时候 | 鲸鱼的话 | 提示行 |
|---|---|---|
| 入场，还没有新消息 | 「嗨，我是{名字}」，停 1.5 秒：新团队用界面语言的默认名字（中文「总管」），重装用团队里 Main Bot 的名字，要导入或读不出名字时不带名字「嗨，我来了」（[启动窗口](2026-10-26-start-window.md) 第 3 节，待定） | 无 |
| 第 1 站：只在数据文件夹这一步比招呼久、出过卡片或换了新文件夹时 | 「先找个地方放东西」 | 无 |
| 离开第 1 站：只在上一句真的说过时 | 「找到了」，停 0.7 秒 | 无 |
| 第 2 站 | 「热身中，等我一下」 | 新团队：「待会儿要接一个模型：DeepSeek 账号或 API Key」；重装：「上次的 6 个 Bot 和 2 个群聊都在」；要导入时没有 |
| 10 秒（第 1、2 站） | 「第一次会慢一点」 | 同上 |
| 45 秒（第 1、2 站） | 「有点久，可能是杀毒软件在查新文件」 | 只有〔打开日志文件夹〕 |
| 游向第 3 站和在第 3 站 | 「开门去了」 | DSH 会挂出「预览版说明」时（会话准备好、主视图里没有非空会话）：「里面先有一页说明，点「继续」就行」；否则留着第 2 站的提示 |
| 就绪 | 「进去吧」，300 ms 后庆祝、潜下去 | 同上，到庆祝开始 |
| 盘不够、又没有更好的盘 | 照那一站说 | 前 10 秒「C 盘只剩 1.2 GB」 |
| 180 秒 | 「等太久了，要不要重试？」 | 无；卡片上只有〔继续等待〕〔重试〕〔打开日志文件夹〕 |
| 启动失败、团队界面没加载出来 | 「DeepSeek Bot 没能启动」「团队界面没有加载出来」 | 无 |
| 有卡片时 | 空着，由卡片自己的第一句说（15/20、600，在已定的文字上面）：推荐盘「C 盘有点挤」（盘不够）或「这里不让我放东西」（没有写入权限），「会放在…」那张「我多加了一层文件夹」，被拒绝的「这里放不了」，找不到数据文件夹「数据不在原来的地方了」；导入的几张见第 4 节；失败的卡没有 | 隐藏 |

- 话跟着鲸鱼走（停在哪一站、正在游哪一段、就绪），从不抢在它前面。每句至少能读 300 ms 才被换掉，一般停 0.9 秒（招呼 1.5 秒，「找到了」0.7 秒）；中间跳过的话以后不补说。失败和 180 秒的问题马上说。「进去吧」等上一句能读满 400 ms 才上，上屏 300 ms 后开始庆祝。鲸鱼沉下去、换个新文件夹重新开始时，话和提示都空着。失败时不画叉，鲸鱼失败的姿势和那句话就是失败。一般的首次启动，用户读到的是「嗨，我是总管」→「热身中，等我一下」→「开门去了」→「进去吧」：数据文件夹这一步通常在招呼读完之前就做完了。
- **一般情况下什么都不问**，用默认位置，但页面上写着放在哪、能换：底注右边一行「数据放在 C 盘（剩 412 GB）· 换个位置…」（[启动窗口](2026-10-26-start-window.md) 第 2、4、6 节），什么都不点就按它走；点「换个位置…」才开系统选择框，定根和下面「一个位置」一样，定好后引擎在新文件夹重新起、鲸鱼沉下去重新开始（启动窗口第 7 节），默认位置上这一次建的文件夹删掉。重装没有这一行，导入复制完以后收起。先看是不是重装（下一条），再看要不要出位置卡片。选位置的卡片只有推荐盘这一张，它上面的按钮都已经试写通过，不会点了再被拒绝；每张卡都说明以后在哪里改：
  - 数据所在的盘不到 5 GB（有团队要导入时，不到「5 GB + 导入卡上要多占的数」），而且有更好的盘：「C 盘只剩 1.2 GB。放到 D 盘（剩 412 GB）？」〔放到 D 盘〕〔仍然放在 C 盘〕，按钮行末尾一个小链接「其他位置…」。按 Enter 就是放到 D 盘。没有更好的盘就不出卡片，只在提示行写一句「C 盘只剩 1.2 GB」，照常启动。
  - 默认位置不能用（没有写入权限）：第一句换成原因「DeepSeek Bot 没有权限在 `C:\Users\<用户名>` 里写文件。」，第二句一样；按钮只有〔放到 D 盘〕和小链接「其他位置…」，没有〔仍然放在 C 盘〕。没有可推荐的盘时只有〔选择其他位置…〕。
  - 保存过的数据文件夹找不到了（多见于以后的启动）：「找不到数据文件夹 `D:\DeepSeek Bot\data`。可能是移动硬盘没插上，或者文件夹被移走、删除了。旧数据不会被改动。」〔重试〕〔重新找到它…〕〔用新的空白团队开始…〕。〔重新找到它…〕不走定根的规则：选中的文件夹本身或它下面的 `data` 里有 `.deepseek-bot` 标记和 `bot/state.json`（所以 `~/.dsh` 永远不算），又通过位置规则（不在 DSH 的家里、不在程序目录里），就把它写成数据文件夹；旁边有 `workspace` 时总工作区一起改过去，没有就不动。否则卡上写「这里没有 DeepSeek Bot 的数据。」，〔重新找到它…〕留着。
- **重装不问。** 没有保存的位置、而 `C:\Users\<用户名>\.ds-bot` 里有团队时（重装过，或者 `%APPDATA%` 被清过），直接接着用：不出推荐盘的卡片，盘不够只在提示行写一句「C 盘只剩 1.2 GB」，要搬去 设置 → 通用 → 位置 →〔移到…〕；写不进去直接是恢复页。第 2 站的提示行写「上次的 6 个 Bot 和 2 个群聊都在」，不写路径，接模型的那句提示也不显示。旧团队登记的总工作区启动页不知道：插件启动后经 `teamWorkspaceChanged` 报告一次，应用据此写 `locations.json` 的 `workspace`。想要空白团队的人去 设置 → 通用 → 位置 →「用新的空白团队开始…」。只认默认位置：放在别处、又没有保存位置的旧数据找不到，和今天一样。
- **推荐的盘**怎么来：只在数据所在的盘不到门槛（5 GB，有团队要导入时加上要多占的数：对话 1.2 GB 加默认要复制的工作文件 3.4 GB，就是不到 9.6 GB）、或默认位置不能用时查一次（重装接着用时不查），正常启动不查。这一步在引擎预热之前，所以迁移用户先看到推荐盘的卡，再看到导入卡。用完整路径的 `%SystemRoot%\System32\WindowsPowerShell\v1.0\powershell.exe -NoProfile -NonInteractive`（`windowsHide`，5 秒超时）读 `Win32_LogicalDisk` 和 `Get-Partition | Get-Disk`：只要固定盘（`DriveType` 3）、`FreeSpace` 不为空、总线不是 USB、SD、MMC 或虚拟盘的，再用 `fs.statfs` 确认一次。盘不够时排除数据现在所在的盘；默认位置不能用时可以推荐同一个盘上的 `X:\DeepSeek Bot`。取剩余空间最大、而且不少于 20 GB 的一个。`X:\DeepSeek Bot` 已经存在时按下面定根的规则判断，不能用就不推荐这个盘。试写只建缺的那几层，写完删掉自己建的。PowerShell 失败、超时或被策略禁掉，都当作没有更好的盘。macOS 和 Linux 不推荐盘，空间不够只在提示行写一句。
- **一个位置。** 用户换位置时只选一个文件夹，由它定出根 `R`：选的是磁盘根目录，`R` 是它下面的 `DeepSeek Bot`；选的文件夹不存在或是空的，`R` 就是它；选的文件夹是 DeepSeek Bot 以前的根（`data` 里有 `.deepseek-bot` 标记，没有团队或者只有一个没说过话的空白团队），`R` 也是它；其余非空的文件夹，`R` 是它下面的 `DeepSeek Bot`。`R` 已经存在、非空、又不是以前的根时，不能用。数据放在 `R\data`，Bot 的文件放在 `R\workspace`（子文件夹的名字待定）；两者是兄弟，互不包含，和默认的 `~\.ds-bot`、`~\DeepSeek Bot` 一样是同一个父文件夹下的兄弟，所有规则不变。〔放到 D 盘〕就是 `D:\DeepSeek Bot\data` 加 `D:\DeepSeek Bot\workspace`。默认安装的路径不改（待定）。设置里也是一处：「位置」一行显示两个路径，一个〔移到…〕一起搬（第 8 节）；要分开放的在「高级」里。
- 只有点了「其他位置…」才打开系统选择框，挂在窗口上，从推荐的盘开始，没有推荐的盘就从现在的数据文件夹的上一级开始。选完先定根，`R\data` 和 `R\workspace` 都对照现在的数据文件夹和总工作区过一遍位置规则，再试写。都通过了：`R` 就是用户选的文件夹时直接用，不再确认；应用加了一层 `DeepSeek Bot` 时，同一张卡片变成「会放在 `D:\DeepSeek Bot`。」〔继续〕〔重新选…〕，只在应用改了用户选的路径时才确认。没通过（没有写入权限、在 OneDrive 里、`R` 是别人的非空文件夹、在 DSH 的家里、在程序文件夹里），卡片写一句原因，〔重新选…〕作主按钮，来时那张卡的〔放到 D 盘〕〔仍然放在 C 盘〕照旧留着；选择框被取消就回到来时的卡。DSH 数据的规则只在那个文件夹真的存在时才检查。位置行的「换个位置…」走同一条路，没有来时的卡：取消就回到位置行，已经出的「会放在…」「这里放不了」也收回。选了现在的根或数据文件夹就当没选；选在现在的数据文件夹里面不行，总工作区还空着时可以成为新的根。
- 首次启动的位置检查和「移到…」用同一套规则检查定出的根：不能是整个磁盘、不能是别人的非空文件夹，外加一次试写。
- `locations.json` 只在引擎第一次成功启动（`ready`）、导入问题也答完之后才写。同时写一份 UTF-16LE 的 `locations.ini` 给卸载程序读。应用自己新建的数据文件夹里放一个不含任何机密的 `.deepseek-bot` 标记，这个标记在建文件夹时就写、不等 `ready`：首次启动没走完就退出时，留下的文件夹下次才认得出是自己建的（定根规则里的「以前的根」），不会被当成别人的非空文件夹。「首次启动没走完就退出时什么都不记」的规则不变：记的只是 `locations.json`。每次启动先删掉上次留下的暂存（路径记在 `%APPDATA%` 里，加上数据文件夹里所有的 `.import-*` 和 `.import-check-*`）。
- 然后加载引擎的页面：DSH 的「预览版说明」→「继续」。DSH 自己的「开始使用」和「添加一个 API Key」不再自动出现：应用在自己的 profile 补丁（和 `search-patch.mjs` 一样经 `runProfile` 的 `patchFiles` 传入）里设 `ui-settings-models` 的 `credentialOnboarding: false`，这是 DSH 有文档的配置。补丁会替换这一行的整个 `config`，所以每次升级锁定的 DSH 都对照新版本重写这一行。应用的补丁里只有这一行。
- **启动失败**时，启动页当场变成恢复页（不再等 GitHub、不再隐藏窗口、不再弹英文「Error」框）：鲸鱼那一行写「DeepSeek Bot 没能启动」，不说俏皮话，下面一句对应的原因（没有写入权限 / 磁盘空间不够 / 程序文件不完整，可能被杀毒软件拦掉了一部分 / 本机引擎启动到一半停下了 / 出了点意外），每种都给〔重试〕〔换个位置…〕〔用新的空白团队开始…〕〔打开日志文件夹〕〔复制详细信息〕（换位置按第 3 节定根的规则，数据和总工作区一起搬，搬的规则同第 8 节：同一个卷上改名，不同的卷上复制完再删旧的；还没有团队时只是换个空文件夹），再加一个「详细信息」折叠区（日志最后 200 行，已脱敏）。
- 启动超过 180 秒：鲸鱼问「等太久了，要不要重试？」，卡片上只有〔继续等待〕〔重试〕〔打开日志文件夹〕，引擎同时继续启动。
- 后台更新器发现了新版本时，恢复页上显示「DeepSeek Bot {版本} 已经发布，可能修好了这个问题。」〔下载并安装〕，带下载百分比和「下载太慢？手动下载」（打开镜像页）。
- 引擎起来了但 DS Bot 界面 20 秒内没报告就绪（ds-bot 在界面挂载完成后调用 `dsBotApp.ready()`）：回到启动页，显示「团队界面没有加载出来」〔重新载入〕〔打开日志文件夹〕〔复制详细信息〕。
- 首次启动期间再双击图标：恢复并聚焦已有窗口，失败页上也一样。
- 建窗口不再依赖「下载」文件夹：每次下载时才取它的位置，取不到就用家目录，再不行就不给默认位置，让用户自己选。
- 日志：`%APPDATA%\DeepSeek Bot\logs\main.log`，2 MB × 3 份轮换，收主进程和引擎的输出；写之前去掉 `token=…`、`sk-…` 和 `/oauth/callback?…` 的查询部分，把用户文件夹的完整路径（如 `C:\Users\<用户名>`）换成 `%USERPROFILE%`。
- 启动页是纯 DOM，CSP `default-src 'self'`；颜色取 [UI 标准](../design/ui-standard.md) 2.1 节 DeepSeek 主题的值，字号用标准里的 13 / 14 / 15 px。它只拿到 `dsBotStart`（`onState`、`act`），只在页面地址正好是启动页文件时才暴露。引擎页面上的 `dsBotApp` 只新增 `ready()`（上面的 20 秒检查）、`focus()`（第 5 节退回系统浏览器登录时回到前台）、`signIn`（第 5 节的登录窗口：`onClosed(原因, 代理)`、`close()`、`openOutside`）和 `foundKeys()` / `takeKey()`（第 5 节现成的 Key），以及主窗口露面时发给页面的一个事件（侧栏磁贴上的鲸鱼靠它浮上来，[启动窗口](2026-10-26-start-window.md) 第 8 节，待定），其余不变；新增的这些只在引擎的页面上、只对主窗口的主框架暴露。主进程对两者分别做精确的来源检查。
- `DS_BOT_HOME` 的一次性运行照旧：不问、不导入，但也显示启动页和失败页。

### 4. 已有 DSH 团队：导入卡

条件：`~/.dsh`（或 `DSH_HOME`）里有 Bot 团队，而数据文件夹里还没有。

- 导入卡在启动页上出现。卡片一出现，两件事就在后台开始，不等用户回答：引擎在新数据位置预热（已定的「先在新数据位置启动一次再复制」照旧），先查团队有没有被 DSH 占着（下面的判断规则）：没占着才把对话复制进暂存文件夹 `.import-<时间>`（在数据文件夹里，和复制时用的是同一个），锁定版 DSH 以暂存为家读一遍它们；占着就只预热引擎，什么都不复制。复制暂存期间锁出现过或刷新过，这份暂存作废，锁放开后重新复制。这份暂存就是复制时要用的那一份：不再另建 `.import-check-<时间>`，对话只复制一次。暂存的路径记在 `%APPDATA%` 里；导入卡开着时关掉启动窗口、更新重开、被杀掉，下次启动都先删掉它。导入卡开着、第一段还没复制完时，主窗口不加载引擎的页面（插件一收到 `state` 就会建出一个空白团队），第 3 站「打开团队」和 20 秒的界面检查也等用户回答以后才开始。点〔先不复制〕：等检查用的引擎退出后删掉暂存，预热好的引擎接着当正式引擎用，主窗口这时才加载它的页面，一秒都不多等。点〔复制过来〕：预热的引擎拿着团队的锁，先停掉它再接着复制 Bot 和附件，复制完起正式引擎，和今天一样。
- 卡片的第一句是鲸鱼的话「找到你以前的团队了」，下面只有一句话和两个按钮：「DeepSeek Harness 里有 6 个 Bot 和 2 个群聊（对话 1.2 GB，工作文件 3.4 GB）。复制过来？」〔复制过来〕〔先不复制〕，下面一行小字「复制后会多占 4.6 GB，DeepSeek Harness 里的原件不动。」，脚注「也可以在 设置 → 通用 → 位置 里复制。」按 Enter 就是复制。「详细」展开才有：
  - 「在 `C:\Users\<用户名>\.dsh` 里找到 6 个 Bot（Chief、写手、程序员等）和 2 个群聊，143 段对话。」
  - 「会复制：Bot、群聊、记忆、对话、附件、模型设置和 API Key。不会复制：MCP、技能和 DSH Agent。DeepSeek Harness 里的内容不会改动，复制以后两边各用各的。」
  - 模型设置自动选一份：先选有 key 的，再按 desktop、web、行数最多的顺序。显示提供商和默认模型，旁边有「更换」，可以按同样的格式换另一份。
  - 可重新生成的文件夹（`node_modules`、`.venv`、`__pycache__`、`.pnpm-store`、`.next` 等）合计 200 MB 以上时，默认勾选「不复制可以重新生成的文件夹」；「先不复制工作文件」默认不勾。卡片上的「工作文件 3.4 GB」和「多占 4.6 GB」按勾选项算：默认已经扣掉可重新生成的文件夹，改勾选时两个数字跟着变。
- **复制分两段，小的先进去。** 第一段挡着启动：Bot、群聊、记忆、对话、附件、模型设置和 API Key（今天 `importTeam` 里除工作文件以外的全部），复制完就启动团队。第二段在团队打开以后由应用在后台做：旧团队工作文件夹里的文件复制到总工作区，不覆盖已有的文件，跳过勾掉的文件夹。导入后每个 Bot 本来就换到新文件夹的新一段，旧文件夹只当历史读，所以工作文件晚几分钟到不影响干活；Bot 在那之前新建了同名文件，旧文件就跳过，记在导入结果里。工作文件还没到齐时（`bot/work-files.json` 是 `pending`），插件在每个 Bot 的系统提示里加一句：工作文件还在从 `<旧文件夹>` 复制过来，还有 N 个，那里只读，要用旧文件先去那里看；跳过的文件数和第二段没开始的原因也写在「复制好了」卡上，不只在设置里。Bot 和群自己设的文件夹（`workDir`）：在 `~/.dsh/bot/workspace` 里面的，改成新总工作区下同样的相对路径（应用的 Bot 不能写 `~/.dsh`）；在别处的两边团队会共用，「详细」里列出这些 Bot 和群。
  - 第二段自己遍历目录树（不用 `fs.cp`），沿用 `copyTree` 的 leave、skip 和 relink（链接最后照旧重建）：每个文件先写进总工作区旁边、同一个卷上的暂存文件夹（`.<总工作区名>.copying-*`，带标记，和换位置的暂存一样），写完用 `fs.link` 放到正式位置；同名文件已经存在时 link 以 EEXIST 失败，就把相对路径记进跳过列表，再删掉暂存里的这一份。不支持硬链接的文件系统（FAT、exFAT）退回到「查一次再改名」，那一小段竞态记进已知限制。Bot 永远读不到写了一半的文件。
  - 记录在 `bot/work-files.json`（`{ from, to, skip, state: 'pending' | 'done', done, total, skipped }`）：`importTeam` 在最后改名之前把它写进暂存的 `bot/`，和团队一起落地；`imported.json` 只记导入的结果。进度在 设置 → 通用 → 位置 里：「正在复制工作文件 820 / 1,204 个，不到 1 分钟」〔停止〕；Main Bot 聊天里的「复制好了」卡上也带一行。退出应用时在文件之间停下，下次启动先删掉上次留下的暂存文件夹，再接着复制；停止后设置里显示「工作文件还有 384 个没复制」〔继续复制〕。第二段进行中，〔移到…〕和换总工作区先停下它。`DS_BOT_HOME` 的运行不续复制。
- **空间只占一份。** 从 DeepSeek Harness 复制时原件必须留下（应用从不写 `~/.dsh`，也不用硬链接连到它的文件：同一个文件两处可见，Bot 在新位置写就改掉了原件），所以多占的空间要在复制前写在卡片上，复制过程中盘上任何时刻最多只多出最后会留下的那一份，复制后设置里能看到原件在哪、占多少：
  - 卡片一出现先查第一段的空间：卡片上的「对话 1.2 GB」是第一段的全部（对话、记忆和附件），要求剩余不少于「第一段 + 500 MB」。够就开始往暂存复制对话并检查；不够就只预热引擎，答〔复制过来〕时出一张卡，第一句「地方不够放」，下面「空间不够：复制要约 1.7 GB，C 盘只剩 1.5 GB，还差 0.2 GB。」〔选择其他位置…〕〔先不复制〕。
  - 暂存在数据文件夹里，和目标同一个卷：对话、`bot/` 和附件都从暂存改名进位，不再把附件从暂存复制第二份。
  - 工作文件的空间在第二段开始前单独查，要求剩余不少于「要复制的工作文件 + 1 GB」，不够就不开始，只在设置里写「工作文件没有复制：D 盘还差 2.2 GB」〔重试〕，不打断启动；复制中剩余不到 500 MB 就停下，设置里写「工作文件没复制完：D 盘只剩 480 MB」〔继续复制〕。暂存加硬链接落位本来就不多占空间。
  - 复制后，设置 → 通用 → 位置 里有一行「DeepSeek Harness 里的原团队还在 `C:\Users\<用户名>\.dsh`（4.6 GB），DeepSeek Bot 不会改动它。」〔打开文件夹〕；要不要删、什么时候删由用户在 DeepSeek Harness 里决定。
  - 新用户从不复制任何东西：推荐盘和「其他位置…」只新建空文件夹，重装接着用原处的数据。应用自己的数据搬动时（第 8 节〔移到…〕、恢复页的〔换个位置…〕）旧位置不留副本。
- 第一段复制时卡片标题是「正在搬过来」，下面是分步进度和数字：「检查对话 23/143」→「复制 Bot 和对话 820 MB / 1.2 GB」→「启动团队」，带剩余时间估计和任务栏进度。〔停止复制〕会就地确认，并说明停下后会留下什么：不留下复制了一半的团队，DSH 里的团队不受影响。
- DSH 正在用这个团队：第一句「DeepSeek Harness 还在用这个团队」，下面「请完全退出 DSH Desktop（任务栏右下角的托盘图标也要退出），并关掉 DSH Web，这里会自动继续。」这张卡在答〔复制过来〕时才出现（卡片一出现就查到被占着时只是不暂存），每 2 秒自动重查，不用点重试，锁一放开就开始暂存和复制；卡上有〔先不复制〕，退不掉 DSH 的人有路可走。判断规则和 ds-bot 的 home-lock 一样：同一台机器上 PID 活着**而且**锁在 60 秒内刷新过（#428 的修法），被系统重用的旧 PID 不再算。
- 有更新版本 DSH 写的对话（下面两张卡的第一句都是「这些对话比我新」）：更新器现在随应用一起启动，找到能读的版本时：「DeepSeek Bot 0.2.4 能读它们，正在下载（37%）。装好后会重新打开，再复制团队。」卡上有〔先不复制〕，还有「下载太慢？手动下载」；下载失败时〔重试〕〔手动下载〕（和恢复页的更新条一样）。位置在这之前不保存，重开后会再问导入。没找到时：「这些对话是更新版本的 DeepSeek Harness 写的，DeepSeek Bot 现在读不了。」主按钮是〔先不带团队开始〕（不再是「退出」），脚注「以后可以在 设置 → 通用 → 位置 里复制。」
- 复制失败（失败的卡没有鲸鱼的第一句）：「团队没有复制完：{原因}。DeepSeek Harness 里的团队没有变化。」常见原因翻成人话（文件被别的程序占用 / 没有权限读取 / 磁盘满了），其他放进「详细信息」。〔重试〕〔先不带团队开始〕〔复制详细信息〕。失败或停止时删掉 `.import-<时间>` 暂存文件夹。
- 导入的修正：群聊的接力 Session（`room.id`）也复制（#551，PR #567）；目标里已有的 `.credentials.yaml` 存着用户自己的 key 或登录时不覆盖。引擎在新数据位置第一次启动时会写一份只有 `client-connection/` 记录（浏览器会话）的 `.credentials.yaml`，这样的文件照常换成旧的。
- 第一段复制完成后，窗口打开在导入来的 Main Bot 的聊天里，先显示一张一次性的卡片「复制好了：6 个 Bot、2 个群聊、143 段对话。工作文件正在后台复制（1,204 个，3.4 GB，还要大约 2 分钟）。」，然后是对模型的检查结果。检查通过显示「模型：DeepSeek-V4-Pro · DeepSeek API　Key 可以用，余额 ¥23.50」；没通过就在用户打字前显示对应的修复卡（见第 6 节）。
- 导入后，Main Bot 在模型检查通过后马上（空闲时）换到新文件夹的新一段（只提前换 Main Bot 待定），并显示「正在把{名字}搬到新的工作文件夹（要读一遍最近的对话，大约 1 分钟）。现在发消息也可以，会排在后面。」其他 Bot 在各自的第一条消息时换段，换段期间先显示用户的消息和「正在搬到新文件夹…」，不再出现 84 秒什么都没有的情况（#384）。

### 5. 接上模型：Main Bot 的设置卡

设置卡是插件的功能，桌面应用、DSH Desktop 和 DSH Web 里都有，下面没注明的地方各形态一样；登录窗口和现成的 Key 一键用要靠应用（`dsBotApp`），只在桌面应用里。

- 桌面应用首次启动交接后，Main Bot 的鲸鱼在侧栏的磁贴上浮上来一次（[启动窗口](2026-10-26-start-window.md) 第 8 节），随后是下面的气泡和设置卡。设置卡的检查、通过和失败驱动磁贴上鲸鱼已有的状态动作（检查时是搜索，通过时是完成）；指针在侧栏里时它的眼睛跟着指针（安静档没有）；减少动态效果时它不动，只有徽标。
- Main Bot 还没有能用的模型时，它的聊天里不再是三个按钮，而是一张卡片（按 UI 标准里提问卡的样式）：
  - 气泡：「你好，我是{名字}，负责管理你的 Bot 团队。开始之前，我需要先接上一个模型。选一种方式：」
  - A「用 DeepSeek 账号登录」，标「推荐」：「不用管理 API Key。没有账号的话，在登录页用手机号就能注册。费用从账号余额里扣；新账号如果有赠送额度，登录后会显示在这里。」主按钮在桌面应用里是〔登录 DeepSeek 账号〕，在 DSH Desktop 和 DSH Web 里是〔在浏览器中登录〕。profile 里没有 DeepSeek 账号功能时不显示 A。
  - B「粘贴 DeepSeek API Key」：掩码输入框（占位「sk-…」）、〔检查并保存〕、「去 DeepSeek 开放平台创建 Key ↗」（`https://platform.deepseek.com/api_keys`）和一句「API 按用量计费，账户里要先有余额。」
  - 底部「用其他模型服务…」打开 DS Bot 设置 → 模型的添加表单。
- **登录**：桌面应用里点〔登录 DeepSeek 账号〕，登录页在应用自己的**登录窗口**里打开，全程不离开应用：
  - 卡片变成「正在登录 DeepSeek 账号…」，带有效期、〔取消〕和一行小字「登录窗口没出来？在浏览器里打开 · 复制登录链接」。登录完成后登录窗口自己关掉，焦点回到主窗口，卡片接着走余额检查。
  - 登录窗口怎么来：DSH 的网页前端在点击时先 `window.open` 一个 `about:blank`（再把它的 `opener` 设成 null），拿到授权链接后用 `location.replace` 把它导过去（今天应用把这一步交给系统浏览器）。这个空白窗口不能当登录窗口：`window.open` 开出来的窗口由 Chromium 建在打开它的页面的 session 里（主窗口默认的、存在磁盘上的那个），`about:blank` 的 webPreferences 也照抄主窗口，`overrideBrowserWindowOptions` 改不了 partition。所以应用照今天的 `setWindowOpenHandler` 允许它、一直隐藏，只当作 DSH 手里的句柄；它第一次要导航时（主框架的 `will-navigate` 或 `will-redirect`），应用拦下这次导航：路径是 `/dsh/authorize` 的，用这个地址新建应用自己的登录窗口；不是的，照今天交给系统浏览器并销毁空白窗口。DSH 只会把它导到自己 `platformOrigin` 上这条固定路径的链接，所以授权页的来源从这次导航取，不读 DSH 的配置，CI 的 loopback 假平台也不用另配。
  - 登录窗口是主窗口的子窗口（`parent` 是主窗口）：系统边框，标题固定为「登录 DeepSeek 账号」，不跟着登录页的标题变（拦下 `page-title-updated`）；内容区 480 × 680，主窗口所在显示器的工作区不到 760 高时，高度改为工作区减 80，登录页在窗口里滚动；居中在主窗口上、整个落在工作区里；不能单独最小化和最大化，随主窗口最小化。`sandbox`、`contextIsolation`，没有 preload、Node 和 webview；用一个不持久的独立 partition（`deepseek-login`）。这种 partition 要到应用退出才没，所以每次关窗都清掉它的存储和缓存（`clearStorageData`、`clearCache`）：应用不保存 DeepSeek 平台的登录状态，下一次登录不会带着上一次的账号，登录的 token 只在引擎的凭据里。新的登录窗口等上一个窗口的清理做完再开：每次登录用的是同一个 partition，清理还没做完就开的窗口，刚拿到的 cookie 会被一起清掉。这个 partition 照 Bot 浏览器的分区（`bot-browser.mjs` 的 `#configure`）拒绝权限请求、权限检查、设备权限和屏幕共享，取消下载；但不照抄它的 `onBeforeRequest`：那条拦下发往引擎本机地址的所有请求，回调就到不了。登录窗口的 session 用自己的 `onBeforeRequest`：发往引擎本机地址（任何本机名加引擎的端口）的请求只放行主框架的 `GET /oauth/callback`，子框架、脚本和其他路径一律拦下，登录页和里面的验证码、扫码框架都碰不到引擎。窗口先隐藏，授权页第一次画出来（`ready-to-show`）再显示。全是 Electron 有文档的接口，不碰 DSH。
  - 允许的地址（只管主框架的导航和重定向，看 `isMainFrame`；登录页里的子框架，比如验证码和扫码，照常加载和跳转）：授权页的来源；主机名是 `deepseek.com` 或以 `.deepseek.com` 结尾的 https 页面；引擎本机地址加 `/oauth/callback` 这一个路径（DSH 的回调）。窗口里的 `window.open`（包括登录页上用户协议、隐私政策这类在新窗口打开的链接）不开新窗口，一律交给系统浏览器，登录窗口留在原来的页面上：登录窗口没有后退，在里面打开就回不到登录页。主框架要去名单外的地址时（比如第三方登录），这次登录换到系统浏览器：应用关掉登录窗口（不算取消），把这次登录的授权链接（不是那个地址）交给系统浏览器从授权页重新开始，并经 `onClosed('browser')` 告诉页面。设置卡和点了〔在浏览器里打开〕时一样，换成「已在浏览器打开 DeepSeek 登录页。登录完会自动回到这里；登录完成前请不要关闭这个窗口。」，有效期、〔取消〕和「复制登录链接」照旧，登录完成后调 `dsBotApp.focus()` 回到前台。同一次登录只在一处进行。
  - 回调一有回应，应用就关掉窗口，不加载回应的那一页（在登录窗口的 session 上用 `webRequest` 看 `/oauth/callback` 这次请求的回应，不论状态码）。有回应不等于登录成功：应用的页面没有 `dshDesktop`，DSH 按网页版回应：成功时回 302 到完成页，这时引擎已经把登录记下来；换取失败时回一页会自己关掉的说明（200）；取消时回 204；作废或重复的回调回 410。登录成没成只看 DSH 的登录状态，卡片照它走。看到回应时，应用先记下这个窗口的回调已经有了回应，再关窗；这次关窗算应用自己关，不发 `onClosed`。之后这个窗口再来的 `did-fail-load`（比如拦下回应造成的 `ERR_BLOCKED_BY_CLIENT`，或 400、410 没有内容的错误页）不算登录页加载失败。
  - 两个窗口同生同灭：失败、过期、取消时 DSH 的前端关掉它手里的空白窗口，应用跟着关掉登录窗口；登录窗口不管因为什么关掉（回调有了回应、用户自己关、加载失败、交给了浏览器、页面调 `close()`），应用都销毁空白窗口：登录成功时 DSH 不关它已经导过的空白窗口，只丢掉引用，在别处登录完成时只有这一条能收掉它。DSH 再开始一次登录时（比如经典 Agent 模式里 DSH 账号菜单的「登录」，它直接调 `start()`），它先关掉旧的空白窗口再开一个新的，Host 回的还是同一次登录：旧登录窗口关掉，新的空白窗口一导航就开出新的登录窗口，这不算取消。登录窗口开着时点鲸鱼菜单的「登录 DeepSeek 账号」或修复卡的登录按钮，只打开 DSH 自己的登录框，显示等待中，它的〔登录〕是灰的，登录窗口不换；在那个登录框里点〔取消〕或 ×，DSH 取消这次登录，登录窗口跟着关掉，设置卡回到两种方式。不管登录在哪里完成，插件在账号变成已登录、或这次登录结束时调 `dsBotApp.signIn.close()` 关掉还开着的登录窗口。
  - 谁关的窗口，应用分得清。只有三种关窗，应用经 `dsBotApp.signIn.onClosed(原因, 代理)` 告诉页面（代理只在 `failed` 时有，见下一条）：`user`（用户按 × 或 Alt+F4，回调请求还没从这个窗口发出）、`failed`（登录页加载失败）、`browser`（主框架去了名单外的地址，交给了系统浏览器）。跟着空白窗口关的、回调有了回应关的、页面调 `close()` 或 `openOutside` 时关的，以及回调请求发出之后用户再关的，都不发。用户关的、而且回调请求还没从这个窗口发出，等于取消：卡片在这次登录还在等浏览器（`waiting-browser`）时调用 DSH 的 `cancel`，回到两种方式的卡；回调请求发出之后再关（用户已经在登录页里登录完，DSH 正在换取和保存），不算取消，不发 `onClosed`，卡片等 DSH 的结果。`failed` 和 `browser` 都不取消。修复卡和鲸鱼菜单走的是 DSH 自己的登录框，没有这张卡：插件从 `settings.models.sign-in` 条目的账号状态取当前这次登录，按同样的规则调 `cancel`，不等它过期。
  - 登录页加载失败（比如断网、代理不对；看主框架的 `did-fail-load`，`isMainFrame` 为真，子框架打不开不算，回调有了回应之后的也不算）：窗口关掉，`onClosed('failed', 代理)`，这次登录不取消；卡片显示「打不开 DeepSeek 登录页。」〔重试〕〔在浏览器里打开〕〔取消〕，有效期照旧；〔取消〕调用 DSH 的 `cancel`，回到两种方式的卡。代理由应用在主进程里取：用登录窗口的 session 对授权链接 `resolveProxy`，取结果第一项的地址（如 127.0.0.1:7890），第一项是 `DIRECT` 时为空；页面自己读不到系统代理。代理不为空时，加一句「登录页走的是系统代理 127.0.0.1:7890：如果代理软件没开，打开它。」，不提第 7 节的「跟随系统代理」开关：登录窗口走应用自己的 Chromium 网络，本来就跟随 Windows 系统代理，那个开关只管引擎。〔重试〕再开始一次登录：Host 回的还是这一次，DSH 开一个新的空白窗口，应用开一个新的登录窗口。
  - 〔在浏览器里打开〕和登录卡小字里的「在浏览器里打开」都走系统浏览器（`dsBotApp.signIn.openOutside`，用这一次的授权链接；登录窗口还开着就由应用关掉，不算取消），卡片换成「已在浏览器打开 DeepSeek 登录页。登录完会自动回到这里；登录完成前请不要关闭这个窗口。」，有效期、〔取消〕和「复制登录链接」照旧；登录完成后窗口回到前台（`dsBotApp.focus()`）；Windows 不允许抢前台时，任务栏按钮闪烁。
  - 登录窗口的地址一律不写进日志，和 DSH 自己的诊断一样不记授权链接：`did-fail-load` 只记错误码和主机名，交给系统浏览器的地址也不记。
  - 登录窗口只在用户点了某个登录入口之后出现，从不自己弹出；它是主窗口的子窗口，启动窗口阶段没有它（[启动窗口](2026-10-26-start-window.md) 第 1 节）。应用接的是 DSH 网页前端的每一次登录，所以桌面应用里不只设置卡：第 8 节的〔重新登录〕、第 6 节修复卡的〔用 DeepSeek 账号登录〕〔改用账号登录〕〔重新登录〕、第 7 节鲸鱼菜单的「登录 DeepSeek 账号」，以及 DSH 自己登录框里的登录，也都在登录窗口里登录。
  - DSH Desktop 和 DSH Web 里不变：按钮仍叫〔在浏览器中登录〕，DSH Web 开新标签页、DSH Desktop 开系统浏览器，卡片写「已在浏览器打开 DeepSeek 登录页。登录完会自动回到这里；登录完成前请不要关闭这个窗口。」。
  - 卡片用的是 `settings.models.sign-in` 条目注入的操作，取法和今天一样（`ctx.slots.entries('settings.models.sign-in')` 的第一个，即现有的 `actions.signInEntry()`）。这些操作有类型声明，但 DSH 没有写成给插件用的接口：每个要调的操作都先确认存在，缺了就退回今天的 `DeepSeekSignIn`。
  - 和 DSH 自己的做法一样：开始登录时 `setOnboarding(true)`；成功、取消、过期、失败，以及卡片卸载时，都调 `setOnboarding(false)` 和 `showLogin(false)`。否则切到经典 Agent 模式时，DSH 的账号菜单会再弹出一个登录框。`start()` 本身失败时按「登录没有完成」处理。
- **粘贴 key**：保存前先检查。只对 DeepSeek 官方地址：`GET https://api.deepseek.com/user/balance`，8 秒超时，不记录 key 和返回内容。`DEEPSEEK_BASE_URL` 指向本机地址时（mock 模型），检查发到那个本机地址的 `/user/balance`；其他自定义地址或中转服务不检查余额，交给第一轮的修复卡。key 只会发给 `api.deepseek.com` 或本机地址。
  - 401：「DeepSeek 不接受这个 Key（401）。请确认整段复制了，或者新建一个。」key 不保存，输入框保留内容和焦点。
  - 格式不对（带引号、带 `NAME=` 等，沿用现有规则）：「只粘贴 Key 本身，不要带引号或 NAME=…」
  - 余额为零：key 保存，卡片显示「Key 没问题，但账户余额是 ¥0.00，充值后才能用。」〔去充值 ↗〕〔再查一次余额〕〔换一种方式〕（回到 A/B 两种方式的卡，已经保存的 key 留着）。
  - 连不上：「暂时连不上 api.deepseek.com，Key 还没保存。如果在用代理软件，确认它开着。」〔再试一次〕〔仍然保存〕。429 或 5xx：「DeepSeek 服务暂时繁忙（{状态码}），Key 还没保存。」同样两个按钮。
  - key 来自环境变量 `DEEPSEEK_API_KEY` 而检查没通过（按 `describe` 的 `source` 认，不按 `writable`）：「环境变量 DEEPSEEK_API_KEY 里的 Key 检查没通过。换一种方式接上就行，在这里保存的 Key 优先于环境变量。」〔换一种方式〕
- **现成的 Key 一键用**（只在桌面应用；看不看剪贴板待定）：卡片出现时应用看两处，找到了就在 A、B 之上多一行「{来源}里有一个 Key：sk-1a2b3…」和〔用这个 Key〕，照样先检查再保存；Key 本身不显示、不进日志。这一行最多一行；它在的时候〔用这个 Key〕是卡上唯一的主按钮，A 的〔登录 DeepSeek 账号〕改成次按钮，「推荐」照旧标在 A 上（UI 标准 10.1：每个界面最多一个主按钮）：
  - DeepSeek Harness 自己的凭据：和导入看同一个家（`DSH_HOME`，没设就是 `~\.dsh`）。先看 `.credentials.yaml` 里 `refs` 下的 `DEEPSEEK_API_KEY`，没有就看那里 `.env` 的同名行；只认 Key，不读 `records` 里的登录记录。那个家给 DeepSeek 设了别的地址时（`.env` 里的 `DEEPSEEK_BASE_URL`，或任何一个 `profiles/*/cordis.patch.yml` 里 `llm-deepseek` 的 `baseURL`，和导入读模型设置的是同一批文件）不出这一行：这把 Key 是给那个地址的，检查会把它发到 `api.deepseek.com`。这一行写「DeepSeek Harness 里有一个 Key：sk-1a2b3…」。装过 DSH、配过 Key、但没有团队可导入（或者答了〔先不复制〕）的人就是这种情况。导入过团队的人，Key 一般已经随 `.credentials.yaml` 或 `.env` 复制过来，设置卡不出现；导入来的 Key 检查没通过时设置卡会回来，这时找到的 Key 和数据位置里已经存的一样，就不出这一行。只读不写，和导入一样。
  - 剪贴板里正好是一个 DeepSeek 的 Key（整段去掉首尾空白后是 `sk-` 加 32 位十六进制，和下面聊天卡认 DeepSeek 格式的规则一样，以实测为准）：这一行写「剪贴板里有一个 Key：sk-1a2b3…」。别家格式的 Key 不出这一行，不把别家的 Key 发去 `api.deepseek.com` 检查。只在设置卡显示期间读：卡片出现时读一次，之后窗口每次回到前台再读一次；只比对格式，不记录；整段值留在应用里，页面只拿到来源和前八位；之后再读到剪贴板变了（窗口回到前台、点〔用这个 Key〕时），这一行按新读到的结果换掉或消失。
  - 两处都有时仍然只有一行：应用在主进程里比对整段值，相同就只算 DeepSeek Harness 那把；不同就显示剪贴板那把，下面一行小字「改用 DeepSeek Harness 里的 Key（sk-1a2b3…）」。
  - 前八位和 DSH 掩码保留的位数一样。点按钮时应用才把值交给页面：`dsBotApp.foundKeys()` 只回来源和前八位，`dsBotApp.takeKey(来源)` 再读一次，读到的仍是一个 Key、前八位也和这一行上的一样时才回整个值，否则不回值、这一行按新读到的结果换掉或消失；页面走和粘贴 Key 完全一样的检查和保存（Host 的 `provider-key`）。401 或余额为零按上面处理，提示写明来源：「DeepSeek Harness 里的 Key 不能用（401）。」，这一行消失。检查没通过（401）的 Key，插件在页面内存里记下它的来源和前八位（应用不知道检查的结果，也不另加接口）：这个页面里之后再读到同一来源、同样前八位的 Key（窗口回到前台、切到别的 Bot 再回来、卡片重新出现），都不出这一行；两处都有时改出另一处那把。重新加载页面后才会再出现。
  - 环境变量里的 `DEEPSEEK_API_KEY` 不用按钮：引擎继承应用的环境（`process.env`），数据位置的 `.credentials.yaml` 里没有这把 Key 时，DSH 的凭据层退回到它，`describe` 报已配置、`source` 是 `env`（`writable` 仍是 `true`），设置卡不出现；只有它检查没通过时才有上面「来自环境变量」那张卡。在这里保存的 Key 写进凭据文件，优先于环境变量，所以〔换一种方式〕之后粘贴或登录都能接上，不用改环境变量。
- **在聊天里粘了 Key 也认**（所有形态）：真实用户会把 Key 直接发到 Bot 的聊天框里，发出去就进了对话记录、还会发给模型。没有能用的模型时 Bot 聊天的输入框本来就锁着（见下面「输入框不可用」那条），粘不进去；所以这张卡管的是接上模型以后的 Bot 聊天和群聊（比如修复卡报 AUTH 时用户把新 Key 发进来；新团队的 Main Bot 要等上手结束，上手期间粘进目标卡输入框的 Key 见第 6 节），以及模型列表还没出来的那一刻。插件观察每个 Bot 和群聊会话的输入稿（DSH 有文档的 `ctx.conversation.input`，每个会话的 `state`），整段去掉首尾空白后正好是一个 `sk-` 开头的 Key（`sk-` 后面 20 个以上的字母、数字、`_` 或 `-`，其中至少一个数字，和 DSH 掩码认 `sk-` Key 的规则一致；别家的 `sk-` Key 也算；DSH 掩码认的其他格式，如 `ghp_`、`AKIA`，不是模型服务的 Key，不拦；带 `NAME=` 或引号的也不拦，和句子里夹着 Key 一样），就给这个会话挂一个 `ComposerBlock`（DSH 有文档的 `ctx.conversation.blocks`：输入框变灰，不能编辑也不能发，输入稿留在里面），并在输入框上方的卡片槽（`conversation.input.dock`，和今天 Bot 要秘密的卡同一处）显示一张卡，按状态选文案：
  - DeepSeek API 还没有 Key：「这看起来是一个 API Key，还没有发出去。要保存成 DeepSeek API 的 Key 吗？」〔检查并保存〕〔当普通消息发送〕〔清掉〕，小字「改一下 · 保存到其他提供商…」。
  - DeepSeek API 已经有 Key：「这看起来是一个 API Key，还没有发出去。要把 DeepSeek API 的 Key 换成它吗？」〔检查并换上〕〔当普通消息发送〕〔清掉〕，小字同上。
  - 不是 DeepSeek 的格式（DeepSeek 的 Key 是 `sk-` 加 32 位十六进制，以实测为准）：「这看起来是一个 API Key，还没有发出去，但不像 DeepSeek 的 Key。要保存到哪个提供商？」〔保存到提供商…〕〔当普通消息发送〕〔清掉〕，小字「改一下」。〔保存到提供商…〕打开 DS Bot 设置 → 模型的添加表单，Key 已经填好（只在页面里传）；保存后 `setDraft('')`、撤掉 block；没保存就关掉表单时，输入稿和 block 留着。
  - 这个 Bot 正有一张要填值的 `request_secret` 卡在等时：「这看起来是{名字}正在要的 Key，还没有发出去。」〔填进那张卡〕〔当普通消息发送〕〔清掉〕，小字「改一下 · 保存成 DeepSeek API 的 Key」。〔填进那张卡〕把输入稿移进那张卡的输入框（卡在对话里时滚到它），`setDraft('')`、撤掉 block。
  - 〔检查并保存〕/〔检查并换上〕：从输入稿取值，走和设置卡完全一样的检查和保存；通过后 `setDraft('')` 清掉输入稿、撤掉 block。没通过时输入稿和 block 都留着，卡上换成检查的结果，〔当普通消息发送〕〔清掉〕和小字「改一下」照旧：401 写「DeepSeek 不接受这个 Key（401）。请确认整段复制了，或者新建一个。」，主按钮换成〔清掉〕，不再有〔检查并保存〕；连不上、429 或 5xx 写设置卡「粘贴 key」里的同一句（「Key 还没保存」），主按钮〔再试一次〕，旁边〔仍然保存〕（已经有 Key 时是〔仍然换上〕），保存后同样 `setDraft('')`、撤掉 block。余额为零时 Key 保存，同样清掉输入稿、撤掉 block，卡片留着，写「Key 已保存，但账户余额是 ¥0.00，充值后才能用。」〔去充值 ↗〕〔知道了〕，点〔知道了〕才收起；这里没有两种方式，不带〔再查一次余额〕〔换一种方式〕。设置卡由状态决定（第 8 节），不在这里写它。
  - 〔当普通消息发送〕：先把这段输入稿记成「放过」，撤掉 block，再调这个会话输入框自己的发送（`ctx.conversation.input.for(会话).submit()`，和点发送按钮同一条路）：输入稿由 DSH 清掉，附件一起发出，发送失败时由 DSH 还原输入稿。DSH 发送时把输入稿清空不算改：输入稿空着、或者又变回这一段时「放过」仍在，所以还原回来的输入稿不再挂 block；输入稿变成别的非空内容时「放过」作废，按新的输入稿重新判断。这条路不带 DSH 的插话设置，回合进行中时一律排进队列。
  - 〔清掉〕：`setDraft('')`，撤掉 block；Key 不保存，也不发出。401 之后也靠它离开。
  - 「改一下」：撤掉 block，输入稿原样留着，焦点回到输入框（`focus()`）；这段输入稿记成「放过」，不再拦；这样记下的「放过」输入稿一改就作废（和〔当普通消息发送〕记下的不同），按新的输入稿重新判断。
  - 一个会话只有一个 block（`ctx.conversation.blocks.set` 是替换，传 `undefined` 清掉的是整个 block），下面「没有能用的模型」的锁和第 6 节上手的锁也用它。所以插件只在一处算这个会话的 block：模型锁 > 上手锁 > Key 的 block，三样都没有才清空。上面说的「撤掉 block」，是去掉 Key 这一层再按这条重新算。
  - 挂着 block 时输入框是只读的（DSH 的 block 让编辑器不能编辑，占位里的原因也只在输入稿为空时显示），用户自己改不了输入稿，出口全在卡片上；输入稿被别处改成别的内容时（比如别的插件调了 `setDraft`），block 和卡片自己消失；切到别的会话再回来、或者重新加载时，按当时的输入稿和「放过」重新判断。「放过」按会话记在页面的内存里，记的是输入稿全文；切到别的会话再回来还在，重新加载就没了。只拦整段是 Key 的输入稿：句子里夹着 Key 不拦，DSH 的掩码只改显示，模型仍会收到。
  - 拦着的时候 Key 只在这个页面里：点了〔检查并保存〕才交给 Host 的 `provider-key`；点了〔当普通消息发送〕，它就和别的消息一样进对话记录、发给模型。但 DSH 本来就把每个会话的输入稿存在浏览器的 localStorage 里（`dsh.conversation.<会话>`；桌面应用里在 `%APPDATA%\DeepSeek Bot` 下，DSH Web 里在用户的浏览器配置里），挂着 block 的这段时间 Key 也在那里，重开后还在，直到输入稿被清掉。
- **账号余额为零**（登录后）：「已登录 DeepSeek 账号，但余额是 ¥0.00。充值后我就能开始；一般一轮对话只要{实测值}，以 DeepSeek 价格页为准。」〔去充值 ↗〕〔再查一次余额〕〔换一种方式〕。key 余额为零时用上面「粘贴 key」里的卡片。这两张卡显示期间，窗口回到前台时、以及每 10 秒（最多 10 分钟）自动重查，余额一到就自己往下走。
- **自动选模型**（插件形态里是否也这样待定）：只有一个提供商能用时，不再让用户选，直接用 DSH 默认模型（能用的话），否则用这个提供商的第一个模型。选之前先确认能用：有不调用模型的检查就用它（账号余额、`/user/balance`；后者是否计费没有文档），没有就发一次 8 token 的试连。通过后卡片收成一行「已接上 DeepSeek-V4.1-Flash · DeepSeek 账号　更换」，随即是 Main Bot 固定的开场白，不调用模型（第 6 节）。这次检查照旧要做：开场白不再用到模型，但检查也挡着 Main Bot 的第一个正常回合。两个以上提供商能用时，仍按提供商分组让用户选，DSH 默认模型标「推荐」。
- 登录 DeepSeek 账号后，DSH 的账号前端会尽力把账号模型存成默认，但这一步不保证完成、也不保证先于我们，所以只剩账号这一个提供商时，DS Bot 自己选账号的第一个模型，不等 DSH。
- 开场白只在确认能用之后才发。聊天记录不会以一行红字开头。
- 没有能用的模型、且模型列表已知时，Bot 聊天的输入框不可用，占位写「先在上面接上模型，我就能回复你」（DSH 有文档的 `ComposerBlocks`）。
- 万一消息在接上模型前就发出去了（比如别的入口），开场白不再被删掉：Main Bot 接上模型后先回答这条消息，再用一句话说明自己是管团队的（模型写的，和今天一样）。这是它的第一个正常回合，用原来的工具，不算在第 6 节上手的 3 次请求里；会话里已经有用户自己发的消息，上手算结束（第 8 节），不再出固定的开场白和目标卡。
- 判断「能用」：catalog 里标了 `needsKey` 的模型不算能用。Host 的默认模型（`pickDefault`、`defaultModel`、`cachedDefault`）、建 Bot、`create_bot` 不指定模型时的回退、模型不再被服务时 `desiredModel` 和 `memory.js` 里的回退、模型菜单（`ModelRows`）和选模型卡片，都只从能用的模型里挑。需要 key 的模型在列表里显示「需要 API Key」，点它打开 key 卡片。
- `needsKey` 只覆盖「profile 写了 `apiKeyEnv`、而凭据未配置」的提供商；DeepSeek 账号这类登录式的提供商永远不会标 `needsKey`，没登录时也在列表里。所以「能用」最终以上面的检查为准，`needsKey` 只是第一道过滤。
- 提供商的显示名：`deepseek-account` 显示「DeepSeek 账号」，`deepseek-official` 显示「DeepSeek API」。中文统一用「提供商」（替换 `i18n.js` 里的「服务商」）。

### 6. 第一条有用的回复

新团队（不是导入来的）接上模型以后，Main Bot 的聊天里先走两步引导，再做第一件事。每一步都是插件画的卡，答完留在聊天里：控件变灰，选过的保持高亮。每张卡都有「跳过设置，直接开始」，点了就结束上手。输入框锁着（`ComposerBlock`，占位「先在上面的卡片里回答」），到上手结束、或者点了第一件事卡的「自己说…」才打开。导入来的团队不走这些，它们是第 4 节的「复制好了」卡和模型检查。

- **开场白**：设置卡收成「已接上 DeepSeek-V4.1-Flash · DeepSeek 账号　更换」那一行后，Main Bot 发一段界面语言的固定文字「你好，我是{名字}，负责你的 Bot 团队。想先让我做点什么？在下面选，或者用自己的话说。」，不调用模型：开场白照旧作为一个回合送进 Main Bot 的会话，插件在它的 `llm/stream` 监听里直接回这段文字，和今天换段时回 `HANDOFF_ACK` 一样。下面照旧一行「工作文件夹：`C:\Users\<用户名>\DeepSeek Bot`　更换」。设置卡收成一行后约 420 ms 是开场白，约 900 ms 是目标卡。
- **目标卡**：标题「最想让团队先帮你做什么？」，同一行一个灰色的「可以多选」。
  - 四个选项〔写东西：文章、周报、文案〕〔写代码、改程序〕〔查资料、做调研〕〔日常杂事：日程、邮件、整理〕是开关按钮（`aria-pressed`，在标签为「想先做什么，可以多选」的一组里）：点一下选中，再点取消，几个都可以选中；选中的带对勾，不只靠颜色。
  - 一个输入框「用自己的话说…」。
  - 〔确定〕是卡上唯一的主按钮，选中至少一个选项、或者输入框里有字时才能点；在输入框里按 Enter 就是〔确定〕，输入法正在组字时不算。
  - 〔跳过〕：不建 Bot，直接出第一件事卡，上面是原来「试试：」的三个固定任务「你能帮我做什么？」「帮我建一个写周报的 Bot」「搜一下今天的科技新闻，挑 5 条讲给我」。这三件事不需要读文件、跑命令或日历权限，不依赖模型自己出题。
  - 答完后选中的选项保持高亮，所有控件变灰，输入框里的字留着；点的是〔跳过〕或「跳过设置，直接开始」时，没有一个选项算选中。
  - 只选了选项：不调用模型，马上出现成的建议（每个目标一组，写在代码里）。
  - 输入框里有字（选没选选项都一样）：调用一次模型。这是一次不带工具的 JSON 调用，和上下文管家的 `askSteward` 同一种形态（固定的提示词，没有 `tools`，经 `ctx.llm.stream`，只回 JSON）；这次调用自己的上限是 `maxTokens` 700、12 秒超时，回答按闭合的 schema 校验，不合就当没有回应。schema 里是 `goal`（`write`、`code`、`research`、`daily`、`general` 之一：四个选项各一个，再加通用的那一组）、一句不超过 18 个字的摘要、最多 3 个 Bot 草案（名字、角色、理由）和最多 3 个第一件事（各带它的草案序号）。
  - 输入框里整段是一个 Key 时（规则同第 5 节「在聊天里粘了 Key 也认」），〔确定〕不调用模型，目标卡下面出第 5 节那张卡（按状态选文案和按钮，没有〔当普通消息发送〕和「改一下」）；保存或〔清掉〕之后输入框清空，目标卡等用户重新回答。输入框照样能改，只要整段还是一个 Key，〔确定〕就不调用模型。
- **合并**：选中的目标按卡上的顺序排，不按点的先后。有文字时，文字的那一组是模型的草案，它属于哪个目标看模型返回的 `goal`（模型没有回应时，文字按关键词对上一组现成的，见下面「模型不可用时」）：`goal` 是所选目标之一时，那一组换成模型的草案，位置不变；是所选以外的目标时加在后面；是通用的、又选了选项时不加（只有文字时就用文字的那一组，通用的也算）。只有一个目标时就是它那一组。几个目标时 Bot 轮流取：先取每组的第一个，再取每组的第二个，以此类推，同名的只留一个，最多 5 个；第一件事是留下的每个 Bot 自己的任务（模型给的任务按它带的草案序号归到 Bot），按 Bot 的顺序，最多 3 个。摘要里每个目标是一个词（写东西 / 写代码 / 查资料 / 处理日常杂事，词里不带「、」），几个目标用「、」连起来；引号里是用户自己的话，超过 18 个字时换成模型给的那句摘要：
  - 只有选项：「想先写东西、查资料：建议建这 N 个 Bot，名字可以直接改。」
  - 选项加文字：「想先写东西，还说了「查一下竞品」：建议建这 N 个 Bot，名字可以直接改。」
  - 只有文字：「按你说的「…」，建议建这 N 个 Bot，名字可以直接改。」
- **建议卡**：摘要下面每个 Bot 一行：勾选框、它的鲸鱼（各用一种颜色）、可以改的名字（最多 12 个字）、角色标签（最多四个字）、一句理由。
  - 〔建这 N 个 Bot〕是主按钮，N 跟着勾选变，一个都没勾时不能点；〔只要{第一个名字}〕的名字跟着第一行的名字变。
  - 〔换一组建议〕：再调用一次模型（同样的调用和 schema），提示词里带上所选目标、用户的话和已经给过的草案，要一组不重复的，换掉卡上的几行，摘要写「换一组：建议建这 N 个 Bot，名字可以直接改。」。目标卡和建议卡合计最多 3 次请求，到了这个按钮就变灰，旁边写「已到上限」；两张卡底部都写着「模型请求 n/3」。
  - 「跳过设置，直接开始」。
- **建 Bot 和第一件事**：点〔建…〕才真的建，这些 Bot 用改过的名字一个个出现在侧栏里 Main Bot 的下面。它们不发模型写的招呼：每个 Bot 的聊天里先是一段固定文字，它的名字加建议卡上那一行的理由（如「你好，我是笔杆。起草文章、周报和文案，照你的口吻改稿。」），和 Main Bot 的开场白一样在 `llm/stream` 监听里回，所以〔建…〕不花一次请求。然后是第一件事卡「第一件事做什么？」：建议里的三个任务，写着用户起的名字（勾掉了 Bot、任务不够三个时，用上面三个固定任务补满），外加「自己说…」（打开输入框，焦点放进去）。点任务等于用户自己发这句话。第一件事（点的任务，或者「自己说…」之后发出的第一条消息）一发出，插件就调用 `restrict` 返回的解除函数、撤掉 guard：它是 Main Bot 的第一个正常回合，用原来的工具，不算在 3 次请求里，也不受下面每一步的 token 和时限。它回复以后，聊天里出现一行灰字「上手结束：{名字}的工具不再受限」，输入框打开。「跳过设置，直接开始」直接解除限制、出这行灰字、打开输入框。
- **模型不可用时**：选项照样给现成的建议。输入框里有字时，建议卡上面写「模型暂时没有回应。先用现成的建议，或者直接开始。」，下面是现成的建议（文字按关键词对上一组现成的，再照上面的规则合并），摘要只写「建议建这 N 个 Bot，名字可以直接改。」；〔换一组建议〕没有回应时显示同一句，原来的几行不变，这次请求照样计数。第一件事的回复失败时，就是下面的修复卡。
- **深度限制是机制，不是提示词**：
  - 步骤表写在代码里，Host 按卡片的回答往下走，模型从不选下一步。
  - 上手期间（开场白到第一件事发出之前），第一个 Main Bot 的会话用 `agent.ctx.tools.restrict({ allow })` 只留 `ask_user` 和输入稿模式的 `create_bot`（只出草案，用户点了才建），`tools.guard` 限制每一步的调用次数，超了就拒绝、要它直接回答。第一件事一发出就解除（上面）。
  - 每一步（每次按〔确定〕或〔换一组建议〕）最多一次请求，输出 400 到 700 token（`maxTokens` 700）：8 秒内没有第一个字、或者 12 秒还没回完，就出这一步的兜底卡。上手期间 Main Bot 的会话里万一跑起一个回合（输入框锁着，只能来自别的入口），它也只有一次请求，8 秒内要有第一个字，整轮 20 秒内完成，否则同样出兜底卡。整个上手最多 3 次请求，就是卡上的「模型请求 n/3」；第一件事不算在里面，它发出时限制已经解除。
  - 每一步都有一张模型关着也能走通的卡。CI 用 mock 模型跑这几种情况：正常、断网、来回循环、答非所问、编造模型名、401、余额为零、把 Key 粘进目标卡的输入框。
- Bot 聊天里任何一轮失败，都由插件画一个修复卡，替换 DSH 的「本轮运行失败」那一行（DSH Agent 的普通会话不变）。原文、代码、HTTP 状态码和 request id 放在「技术详情」里，可以复制；AUTH 的原文照旧不显示。

| 代码 | 卡片 | 按钮 |
|---|---|---|
| MISSING_CREDENTIAL | 「{名字} 用的模型还没有 API Key。」 | 填入 API Key / 用 DeepSeek 账号登录 / 换个模型 |
| INVALID_CREDENTIAL | 「这个 API Key 的格式不对。」 | 重新填 Key / 换个模型 |
| AUTH | 「{提供商} 不接受现在的 API Key（{状态码}）。」 | 重新填 Key / 改用账号登录 / 换个模型 |
| QUOTA | 「{提供商} 的余额或额度不够了（{状态码}）。」 | 去充值 ↗（只有 DeepSeek 官方时）/ 重试 |
| ACCOUNT_QUOTA | 「DeepSeek 账号余额不足。」 | 去充值 ↗ / 重试 |
| ACCOUNT_SIGN_IN_REQUIRED、ACCOUNT_SIGNED_OUT、ACCOUNT_TOKEN_INVALID | 「DeepSeek 账号的登录失效了。」 | 重新登录 |
| TRANSPORT、TIMEOUT | 「连不上模型服务。」在用系统代理时加一句「现在走的是系统代理 127.0.0.1:7890：如果代理软件没开，打开它，或者在 设置 → 通用 → 网络 里关掉「跟随系统代理」。」 | 重试 |

- 卡片按失败代码选，不看原文（DSH 也是按代码分流的，原文和 `failureMessage` 都是它的内部细节）。提供商名字和状态码取自这次失败的路由和 HTTP 状态，不写死「402」或「DeepSeek」：QUOTA 也可能来自别的状态码和别的提供商。`noteTurnFailure` 今天只把状态码和 request id 写进诊断日志，要新增到 Bot 的状态里（`bot.blocked`），经 `api/bot` 给卡片读。
- 「重试」让 Bot 接着做，不会把用户的话再发一遍。充值回来后自动重查余额，并接着做。
- Bot 的招呼（第一个 Main Bot 的固定开场白和建议卡建的 Bot 的固定招呼除外，它们不调用模型）因为凭据或余额失败时，重新留着，下一次检查通过时再发。

### 7. 第一个小时

- **命令沙盒启动不了命令**（#523，`exit code 3221225794`，DSH 的问题）：工具结果下面显示「这台电脑上，DeepSeek Harness 的沙盒启动不了命令（错误 0xC0000142），不是命令本身的问题。可以给 {名字}「完全权限」，或者在它请求时批准单条命令。」〔打开 {名字} 的权限设置〕〔先不改〕。给完全权限照旧要二次确认、照旧标红。Bot 也会收到一条说明，改为请求批准，而不是盲目重试。
- 没有装 PowerShell 7 的 Windows 上，提示词里写明命令跑在 Windows PowerShell 5.1：不能用 `&&` 和 `||`。
- **系统代理**（仅桌面应用；默认开待定）：用户自己没设 `http_proxy` / `https_proxy` / `all_proxy`（任何大小写）、数据位置的 `.env` 里也没有时，应用用 `session.resolveProxy` 读 Windows 系统代理，作为启动环境传给引擎。
  - `resolveProxy` 返回的是 Chromium 的 PAC 结果列表（`;` 分隔，可能有 `PROXY`、`HTTPS`、`SOCKS`、`DIRECT`）：按顺序取第一个可用项，遇到 `DIRECT` 就停；`PROXY h:p` 写成 `http://h:p`，`HTTPS h:p` 写成 `https://h:p`，一律带协议（DSH 不认没有协议的 `h:p`）；SOCKS 跳过（DSH 也不支持），相关提示改为「系统代理是 SOCKS 类型，DeepSeek Bot 用不了；请在代理软件里打开 HTTP 端口，或设置 https_proxy」。
  - 不设 `NO_PROXY`：DSH 自己会让本机地址直连，而 Windows 上同名不同大小写的环境变量只会传一个，设了反而可能盖掉用户的 `no_proxy`。PAC 可能对不同主机给出不同答案，按 `api.deepseek.com` 解析只是近似。
  - 代理变量只放在启动环境里，绝不写进 profile 文件夹的 `.env`（DSH 会拒绝那里出现代理变量）。应用自己的更新下载走 Chromium 网络栈，本来就跟随系统代理，不受这项影响。
  - 设置 → 通用 → 网络里有开关「跟随系统代理」，打开时旁边显示现在的系统代理（如 127.0.0.1:7890）。「连不上 GitHub」加一句代理提示。
  - 验证 `NODE_USE_SYSTEM_CA` 在 `ELECTRON_RUN_AS_NODE` 下有效后，才在引擎的启动环境里设它；验证不了就不设。
- 冷启动时 Bot 列表不会是空的（#559）：第一次挂载后检查团队侧栏是否真的出来了，没有就重新挂载一次；「回到 Main Bot」的逻辑移出 `TeamSidebar`。
- Bot 还在干活时关窗口，先问「有 2 个 Bot 还在工作，关闭窗口会让它们停下。」〔仍然关闭〕〔取消〕（#500）。
- 鲸鱼菜单增加「模型和 API Key」，以及未登录时的「登录 DeepSeek 账号」。桌面应用里「切换经典 Agent 模式」只放在 设置 → 通用。

### 8. 以后的启动和回头入口

- 以后每次启动也显示启动页：64 px 的鲸鱼和「正在打开你的团队…」，没有水线和圈，也没有第 3 节鲸鱼的话和提示；10 秒起显示「已用 N 秒」，45 秒「比平时慢，请再等一会儿」〔打开日志文件夹〕，180 秒和首次启动一样（[启动窗口](2026-10-26-start-window.md) 第 5 节）。然后打开上次的 Bot（预计 3 到 12 秒，以后的启动还没实测）。
- 设置卡由状态决定：没有能用的模型（跳过过、删了 key、退出了登录），Main Bot 的设置卡就回来；账号登录过期时显示「DeepSeek 账号的登录失效了。」〔重新登录〕（桌面应用里同样在登录窗口里登录）。
- 目标卡、建议卡和第一件事卡（第 6 节）只在新团队接上模型、上手还没结束时出现。上手结束看 Main Bot 的会话：里面有那行「上手结束」的灰字、或者有用户自己发的消息（第一件事也是），就算结束，从会话里读，不另存标记；结束以后它们不再回来，设置卡回来时也不带它们。上手中途关了应用、或者模型没了：重开或重新接上模型后从目标卡重新开始，开场白不再发，已经建好的 Bot 留着，`restrict` 和 guard 重新挂上（它们只在内存里），「模型请求 n/3」从 0 算起。导入来的团队从来不出。
- DS Bot 设置 → 模型在所有形态里都有（在 `team-actions.js` 里接上插件 Host 已有的 `providers`、`provider-key` 等接口，今天只有停用的 `app/ui` 接了），显示每个提供商的 key 状态（「已设置 Key」「需要 API Key」「Key 来自 DS Bot 之外」）和「添加提供商」。原来的「Harness 设置」改叫「高级设置（DeepSeek Harness）」。
- 要打开 DSH 自己的模型页时（「高级设置」里的模型、鲸鱼菜单的「模型和 API Key」在没有 DS Bot 模型页时），直接落在「模型」上，不再落在「通用设置」：插件注册一个自己的 `settings.onboarding` 步骤，自动检查时立刻完成、什么也不画；被 `openOnboarding(id)` 明确打开时调用 DSH 交给步骤的 `openSection('models')` 再完成。这些都是 DSH 有文档的接口。
- 设置 → 通用 → 位置（桌面应用）：「位置」一行显示数据文件夹和总工作区，各有〔打开〕，一个〔移到…〕把两个一起搬到新的根 `R` 下面的 `data` 和 `workspace`（定根和首次启动同一条规则）。搬是搬，旧位置不留副本。确认写明会搬什么、删什么：「会把数据和工作文件搬到 `D:\DeepSeek Bot`。搬完后 `C:\Users\<用户名>\.ds-bot` 和 `C:\Users\<用户名>\DeepSeek Bot` 会删除。」〔搬过去〕〔取消〕。搬之前先查目标卷的剩余空间（不同的卷要「数据 + 要搬的工作文件 + 1 GB」），不够就在确认里说清差多少，不动手。
  - 只搬应用自己建的文件夹。数据文件夹看 `.deepseek-bot` 标记；总工作区没有标记，应用建它时（默认的 `~\DeepSeek Bot`、`R\workspace`）在 `locations.json` 里记一笔 `workspaceCreated`。用户自己挑的现成文件夹（老版本允许过的 `D:\`、`D:\Projects`，「高级」里设的）不搬也不删：团队改用 `R\workspace`，旧文件夹原样留下，设置里写「旧的工作文件夹 `D:\Projects` 原样保留」。没有标记的数据文件夹按卸载的清单逐条搬（同一个卷逐条改名，不同的卷逐条复制再删），清单外的东西不动，`R` 不能在清单里的条目里面。
  - 先在 `%APPDATA%` 写一份「搬到一半」的记录（从哪、到哪、改名还是复制、到了哪一步），再停引擎。同一个卷上，数据文件夹和总工作区各自改名过去，不复制、不多占、立刻完成；改名失败（文件夹被资源管理器或编辑器开着）就退回到复制那一支。不同的卷上，数据经暂存复制到 `R\data`。两种情况都在副本的 `bot/state.json` 里删掉 `workspaceId`（和导入一样）。重开的进程按这份记录在新位置启动，`DS_BOT_WORKSPACE` 指向 `R\workspace`，插件在下一个回合登记它，用总工作区的 Bot 和群照常换段；新引擎 `ready` 之后才写 `locations.json`，然后删掉旧的数据文件夹（复制那一支；有标记整个删，没标记只删清单里的条目），记录转成「总工作区还在搬」。没到 `ready`、或者中途被杀掉：下次启动按记录退回，改名的改回去，复制的删掉应用自己建的 `R\data`，再在原来的位置启动，记录删掉。恢复页的〔换个位置…〕走同一套。
  - 总工作区里的文件在重开后由应用后台搬到 `R\workspace`（和导入的第二段同一套，记录在 `bot/work-files.json`）：每个文件先进同卷暂存、硬链接落位，落位成功、原件的大小和修改时间没变就删掉原件（链接只删链接本身，不跟进去）；新位置已经有同名文件的跳过，留在原处；Bot 或群自己设的文件夹在旧总工作区里面时，那棵子树不搬，照旧归它们；扫描之后才写进旧文件夹的文件不在清单里，留着。最后删掉空的文件夹。设置里写「旧文件夹里只剩 3 个没搬过来的文件（新位置已经有同名文件）」〔打开旧文件夹〕。「高级」里才能单独换其中一个，换总工作区照旧不用重启。
  - `~/.dsh` 有团队时有「从 DeepSeek Harness 复制团队…」：复制到一个新的数据文件夹（现在的旁边，名字加序号，先过第 4 节第一段的空间检查），现在的团队不删：只有一个没说过话的空白 Main Bot 时，`ready` 之后删掉它；有用户的对话就留着，「位置」里多一行「以前的团队还在 `C:\Users\<用户名>\.ds-bot`（0.8 GB）」〔切回〕〔打开文件夹〕〔删除…〕，也记进 `locations.ini`，卸载时选「是」能按同一张清单清掉它。导入过的另显示 DeepSeek Harness 原团队的位置和大小（第 4 节）；工作文件还在后台复制时显示进度和〔停止〕，停过或没复制完的显示「工作文件还有 384 个没复制」〔继续复制〕；还有标红、要点两次的「用新的空白团队开始…」（在新文件夹新建，现在的数据同样留着，列在「以前的团队」里）。只有〔移到…〕和恢复页的〔换个位置…〕删旧的；复制团队和空白团队都在新文件夹里完成，新引擎 `ready` 之后才切换 `locations.json`，失败就继续用原来的，不需要恢复。
- 设置 → 关于：下载更新时显示百分比和大小（「正在下载 0.2.4（37%，78/212 MB）」），「下载失败」和「没能检查更新」分开，各带〔重试〕〔手动下载〕；「保存诊断信息…」把诊断表和日志最后 200 行存成一个 .txt（默认放桌面），报问题不需要能上 GitHub。反馈页里形态显示为「DeepSeek Bot 应用」（今天会误报成 DSH Web）。

### 9. 卸载和重置

- 卸载时先是 NSIS 的「确定要卸载吗」，然后只多问一个问题，默认「否」：「要同时删除 DeepSeek Bot 的数据吗？会删掉对话、Bot、记忆、API Key 和登录信息：{数据位置}，以及 {壳数据}。数据文件夹是 DeepSeek Bot 新建的，会整个删除；否则只删除 DeepSeek Bot 自己的文件。不会删除 Bot 的工作文件夹 {总工作区}（里面是你的文件）。选「否」会全部保留，重新安装后接着用。」
- 选「是」：数据文件夹有 `.deepseek-bot` 标记就整个删掉；没有标记（老版本装的，或者老版首次启动允许过的 `D:\`、非空文件夹）就只删应用和 DSH 自己的条目（`bot`、`profiles`、`sessions`、`attachments`、`storages`、`.anonymous-user-id`、`.credentials.yaml`、`.env`、`.import-*`、`.import-check-*`），删完是空文件夹才删文件夹本身。换数据位置的暂存在数据文件夹旁边（`.<文件夹名>.moving-*`），不在里面。磁盘根目录、家目录和总工作区永远不删。再删 `%APPDATA%\DeepSeek Bot` 和 `%LOCALAPPDATA%\deepseek-bot-updater`。
- 静默卸载（`/S`，包括 winget）和更新时的卸载（旧卸载程序带 `/S --updated` 运行）不问、不删（CI 现有的「卸载后数据还在」检查照旧通过）。
- 一键安装模式下，卸载程序在 `customUnInit` 之前已经被设成静默，`${Silent}` 分不出用户的 `/S` 和正常卸载，所以真正起作用的是重新解析命令行里的 `/S` 和 `--updated`，有任一个就不问。提问用不带 `/SD` 的 MessageBox（带了在一键模式下就永远不显示），加 `MB_SETFOREGROUND`，因为这时没有卸载窗口可依附。提示文字用 LCID 1033 和 2052 定义自己的 LangString（`installer.nsh` 被包含时 `${LANG_ENGLISH}` 等常量还没定义）。模板顺序是 electron-builder 的内部细节，升级它时由 CI 的交互式卸载测试把关。
- README.md 和 README.zh.md 都增加「卸载和重置」一节，用 `%APPDATA%`、`%LOCALAPPDATA%`、`%USERPROFILE%` 写出 Windows 上的实际位置。

## 需要 DSH 提供的

不打补丁，以下向 DSH 提需求：

1. 给网页版的「预览版说明」一个有文档的关闭开关（和 `credentialOnboarding` 放在一起），供嵌入它的应用使用。
2. 修 Windows 沙盒在 Electron（`ELECTRON_RUN_AS_NODE`）里启动 pwsh 时的 `0xC0000142`（#523 有复现），并报一个有结构的错误码，不要只给退出码。
3. `MISSING_CREDENTIAL` 在聊天里显示本地化的一句话，不显示提供商路由和环境变量的原文；AUTH、QUOTA 的失败节点带上 HTTP 状态码（不带 key）。
4. 把 `settings.models.sign-in` 条目注入的操作（`start`、`cancel`、`showLogin`、`setOnboarding`、`refreshAccount`、`hooks.account` 等）和 `credentialOnboarding` 声明为跨版本稳定的插件接口，或者提供一个有文档的「开始 DeepSeek 登录、读余额」的客户端 API。
5. 一个不扣费、也不需要插件读回 key 的凭据检查（`ok / invalid / no-balance / unreachable`），并给模型页的 key 编辑框加上实时检查。
6. `listModels` 标出哪些模型的提供商还没有凭据（PR #316 的后续）。
7. 网页版余额不足的提示加一个充值按钮（今天在没有 `nativePlatform` 时只是一个 Toast）；这条提示能按 Session 区分，或者让插件接管自己的 Session。
8. 登录完成页提示用户回到原来的应用；应用已经关掉、回调地址失效时给出清楚的提示。
9. 让 DSH 的代理跟随 Windows 系统代理（含 PAC），并考虑信任系统证书库。
10. `settings.launcher` 插槽能直接打开设置的某一节（比如「模型」）。今天可以借一个自己的 `settings.onboarding` 步骤绕一步做到（见第 8 节），有了这个接口就更简单。
11. `runProfile` 报告命名的启动阶段，供壳显示真实进度。
12. pwsh 工具的说明里写明实际是 Windows PowerShell 5.1 还是 PowerShell 7。
13. 发送前的一个有文档的钩子（或者让 `ComposerBlocks` 能带一张卡片），让插件能在一段只有 Key 的消息进对话记录之前拦下它；今天只能靠观察输入稿再挂 block，粘贴和 Enter 同一瞬间时拦不住。
14. 网页前端（或 Desktop 桥）提供「把授权页交给宿主自己的窗口打开」的方式；今天桌面应用只能接住网页前端 `window.open` 的 `about:blank`，再看它导去哪里。

## 验收

- 打包后的 Windows CI，用名为「测试 用户」、没有「下载」文件夹、没有 `~/.dsh` 的一次性用户：进程启动后 2 秒内窗口可见（目标 1 秒，CI 留余量）；引擎的页面之前不出现任何卡片；能进到引擎的页面。
- 启动页（同一个 CI，中英文各一遍）：首次启动没有标题、三站的标记和说明段落；鲸鱼的话按第 3 节的顺序出现，每句至少能读 300 ms 才被换掉，跳过的不补；提示行只在第 2、3 站有字（例外是盘不够时前 10 秒的「C 盘只剩 1.2 GB」和 45 秒的〔打开日志文件夹〕）；「已用 N 秒」5 秒起出现；在 720 × 540 和 720 × 500 下没有一行字折行或被省略号截断，页面不能滚动；读屏的「启动进度」列表和朗读区照旧报阶段。
- 交接：首次启动 `handoffShow` 在鲸鱼停到第 3 站后 1.3 秒内（原型实测 1.09 到 1.17 秒）；启动窗口在约 300 ms 里至少经过一个中间尺寸，长到主窗口的矩形；主窗口在鲸鱼停到第 3 站后 2 秒内可见，矩形和启动窗口长成的一样（`ready()` 到达时鲸鱼还在游的，这两个时间最多各晚 600 ms）；页面不发 `handoffShow` 时，主进程在 `ready()` 后 2.5 秒自己显示主窗口（以后的启动 0.8 秒，重试或重新开始后庆祝的那次也是 2.5 秒）；减少动态效果时窗口不长大，`handoffShow` 时主窗口直接出现。
- 首次启动期间没有一个 `dialog.show*` 不挂在主窗口上（单元测试扫描调用处），窗口出来之前没有系统对话框；位置和总工作区不问（没有「欢迎」对话框），系统选择框只在点了位置行的「换个位置…」以后出现，取消它什么都不变。
- 数据所在的盘不够 5 GB（CI 用替身的空间查询）：只有一张卡片、一个主按钮，按 Enter 就过，不出现系统选择框。枚举盘的 PowerShell 只在盘不够或默认位置不能用时运行一次，正常启动和重装的日志里没有它；没有剩余 20 GB 以上的其他固定盘时不出卡片，提示行写剩余空间。〔放到 D 盘〕之后 `D:\DeepSeek Bot\data` 和 `D:\DeepSeek Bot\workspace` 都存在，`locations.json` 指向它们；〔仍然放在 C 盘〕之后 D 盘上没有留下试写建的文件夹。
- 有 `~/.ds-bot` 团队、没有 `locations.json` 的一次性用户：没有卡片，C 盘不到 5 GB 时也没有，第 2 站的提示行写「上次的 N 个 Bot 和 N 个群聊都在」（数字是那个团队的），进去就是原来的团队。
- 导入：点〔复制过来〕后，对话复制完团队就打开，`bot/work-files.json` 记着工作文件没复制完；工作文件在后台到齐后记成已完成；复制一半退出再启动会接着复制，已有的文件一个不覆盖；〔先不复制〕不重启引擎，暂存已删。
- 空间只占一份（CI 用替身的空间查询和一个 2 GB 的假团队）：整个导入过程中数据所在的盘最多少掉「第一段 + 500 MB」，没有 `.import-check-*` 文件夹，`~/.dsh` 的内容和修改时间一个都没变；工作文件复制完后新旧两处各一份，设置里显示原团队的位置和大小；剩余空间降到 500 MB 以下时后台复制停下，设置里有〔继续复制〕。导入卡开着、DSH 还占着团队时数据文件夹里没有 `.import-*`，锁放开后才出现；暂存期间锁刷新过，暂存会重做；导入卡开着时关窗、更新重开，下次启动前暂存已删。
- 〔移到…〕同一个卷：完成不超过 2 秒，旧路径不存在，数据没有被复制（inode 不变）；改名失败时退回到复制；不同的卷：新引擎 `ready` 后旧数据文件夹被删，工作文件逐个落位后原件被删，复制完旧总工作区里只剩跳过的文件，数量和设置里写的一致；用户自己挑的总工作区一个文件都不动；新引擎没 `ready` 或中途被杀掉时，下次启动退回原位置，`R` 下面没有留下应用建的东西，`locations.json` 不变。
- mock 模型粘贴 `sk-test-ok`：第一个 Main Bot 的 Session 里没有失败节点，引擎的页面出来后 30 秒内收到开场白，mock 模型没有收到开场白的请求（只有余额检查），随后出现目标卡；CI 上从双击安装包到目标卡不超过 90 秒。
- 上手（mock 模型）：只选选项按〔确定〕时 mock 没有收到请求，卡上是「模型请求 0/3」；输入框里有字时正好一次；合并后的建议按第 6 节的规则排（卡上的顺序、轮流取、同名只留一个、最多 5 个 Bot、最多 3 个第一件事），和点选项的先后无关；〔换一组建议〕到 3/3 后变灰，写「已到上限」；〔跳过〕给出三个固定任务；〔建…〕后侧栏里正好多出勾选的那几个 Bot，用的是改过的名字，每个的聊天里是固定的招呼，mock 收到的请求数不变；第一件事发出之前，Main Bot 会话的工具只有 `ask_user` 和输入稿模式的 `create_bot`，第一件事那一回合已经是原来的工具；目标卡输入框里整段是末四位 `0001` 的那把 DeepSeek 格式 Key 时按〔确定〕，mock 没有收到请求，卡下面是 Key 的卡；Main Bot 的会话里有那行灰字或用户的消息时重开应用，不再出目标卡，都没有时从目标卡重新开始；第 6 节列的八种情况都走到一张能用的卡，每张卡都有「跳过设置，直接开始」。

## 不做什么

- 不在应用里另做一套配置模型的欢迎向导：模型只在 Main Bot 的设置卡和 DS Bot 设置 → 模型里配。目标卡、建议卡和第一件事卡也是插件在 Main Bot 聊天里画的卡，不是应用的向导。
- 上手期间不让模型选下一步，也不让它自己一轮轮地调用工具：步骤表在代码里，由卡片的回答推进，Main Bot 的工具受限到第一件事发出（第 6 节）。只选了目标卡的选项时不调用模型。
- 鲸鱼的话从不是一段话：一次一句，一行放得下；启动页上不放说明段落，也不轮播提示。
- 不在设置卡显示期间之外读剪贴板；剪贴板和 DeepSeek Harness 里的 Key 都不自动保存：一定是用户点了按钮，再按「粘贴 key」的规则检查和保存。
- 设置卡的现成 Key 只认 Key，不单独搬 DeepSeek Harness 里的账号登录（grant 记录归 DSH 的账号模块，应用不去写）：没导入团队、或者答了〔先不复制〕、在 DeepSeek Harness 里用账号登录过的人，在登录窗口里再登录一次。导入团队时 `.credentials.yaml` 整个复制（目标里已有用户自己的 key 或登录时除外），账号登录跟着过来，不用再登录。
- 不伪装 `dshDesktop`，不用 CSS 或 DOM 去藏、改 DSH 的界面；DSH 的「预览版说明」等它的开关。也不预先写入它的「已读」版本号（`ui-settings-general` 的 `welcomeNoticeVersion`）：那等于替用户点了「继续」，版本号也没有公开导出，写在补丁层里还会让用户以后点「继续」时保存失败。
- 不改 DSH，不依赖 DSH 安装里的文件。DSH 的内部接口只用已经在用的 `@deepseek-ai/dsh-app-boot`、`@deepseek-ai/dsh-session-format`、`@deepseek-ai/dsh-session-format-catalog` 和 `settings.models.sign-in` 条目注入的操作（设置卡会多调 `setOnboarding`、`showLogin`、`cancel`、`refreshAccount`，见「已知限制」），不再新增。
- 不在每次启动时扫盘：固定盘只在盘不够或默认位置不能用时枚举一次；读卡器、U 盘、移动硬盘、网络盘和光驱一概不碰，也从不推荐它们。
- 卸载从不删除总工作区、磁盘根目录和家目录。
- 日志、复制出来的详细信息、诊断文件和文档里不出现 key、token 和真实的用户路径；界面上的位置只给用户本人看。截图只用一次性目录。
- 不用其他产品的文字、图标和插图（包括 DSH Desktop 的欢迎页插图和字体）；信任说明用自己画的示意图。

## 已知限制

- DSH 加开关之前，「预览版说明」仍然是引擎页面的第一屏，用户要多点一次「继续」；每个新的数据文件夹（以后的导入、重新开始）都会再出现一次。启动页只能提前提醒。
- 设置卡调用的是 `settings.models.sign-in` 条目注入的操作。它们有类型声明，但 DSH 没有写成给插件用的接口，rc 版本之间可能变化。缺了哪个就退回到今天的 `DeepSeekSignIn`；每次升级锁定的 DSH 都要重测（另见「需要 DSH 提供的」第 4 条）。
- `credentialOnboarding` 那一行的 id 如果在 DSH 里改了名，补丁只会留下一条警告、悄悄失效；靠验收里对 `__DSH_MODELS_ONBOARDING__` 的检查发现。
- `GET /user/balance` 不在聊天 API 里，是否计费没有文档；它证明的是 key 和余额，不是模型能不能用。除了 401 以外的失败都不拦人，第一轮的修复卡兜底。
- 自动选模型时，没有不调用模型的检查的提供商要多一次 8 token 的试连。
- 开场白是固定文字，不再花钱，但也说不出任何只有模型才知道的东西。
- 上手里模型的那一步比卡片慢：真实的网络往返，最坏 12 秒才出兜底卡（8 秒内来了第一个字、之后停住的）；它先花钱（只在用户写了字或要换一组时），才见效果；措辞每次不一样，CI 只能测结构。
- 合并后的第一件事偏向前两个目标：三个以上目标时，后面的目标没有第一件事；勾掉前面的 Bot 时，用三个固定任务补满，不用后面 Bot 的任务（怎么分见「待定」）。
- 首次启动主窗口在就绪后约 1.6 秒才露面（原来约 620 ms），以后的启动约 0.6 秒（原来 120 ms）：多出来的主要是等纸面空下来再长大的约 460 ms，首次启动还有「进去吧」先停的 300 ms。
- Bot 聊天里余额不足时，DSH 自己的余额提示（不分 Session）会和修复卡同时出现。
- 中文默认名字看的是第一次请求时的界面语言；DSH 存的语言偏好还没加载完时，它可能还是浏览器的语言，所以浏览器是英文、DSH 设成中文时，新团队仍可能叫 Chief。桌面应用里全新的数据位置以系统界面语言为准。
- 退回系统浏览器登录时，Windows 的前台规则可能不让窗口在登录后回到前台，这时只能靠任务栏闪烁和卡片自己的「已登录」状态。
- 登录窗口靠的是 DSH 网页前端「先开 `about:blank` 再导到授权页」的做法，不是接口；DSH 改了做法就退回系统浏览器（另见「需要 DSH 提供的」第 14 条）。登录页里主框架走出 DeepSeek 域名的流程（比如第三方登录）会换到系统浏览器从授权页重新开始，登录窗口里填到一半的东西不带过去。
- 登录窗口不留 DeepSeek 平台的登录状态，〔去充值 ↗〕（余额为零的卡、ACCOUNT_QUOTA 的修复卡）仍在系统浏览器里打开开放平台：没在浏览器里登录过开放平台的人（比如刚在登录窗口里用手机号注册的新账号）要在那里再登录一次。以前在浏览器里登录时没有这一步（要不要改见「待定」）。
- 修复卡和鲸鱼菜单走 DSH 自己的登录框，登录窗口开着时它仍写着在浏览器里继续：这是 DSH 的文案，不改它的界面。在那个登录框里点〔取消〕或 ×，会取消这次登录，登录窗口也跟着关掉。
- 剪贴板只在设置卡显示期间读，但读的时候没有提示；卡上那一行的前八位就是读过的证据。
- 聊天里只有 Key 的输入稿靠观察输入稿再挂 block，粘贴和 Enter 同一瞬间（脚本、自动化）可能抢在 block 之前发出去；句子里夹着的 Key 不拦，DSH 的掩码只改显示。
- 聊天里只有 Key 的输入稿在清掉之前一直存在浏览器的 localStorage 里，这是 DSH 存输入稿的做法；401 或用户不理卡片时，Key 会跟着输入稿留到下次启动。插件只在保存、〔填进那张卡〕或〔清掉〕时用 `setDraft('')` 清掉它；〔当普通消息发送〕时由 DSH 发出后清掉；插件不替用户删输入稿。
- 签名之前，开着智能应用控制的 Windows 11 装不了未签名的安装包，只能先走 DSH Desktop 插件这条路。签名主体如果是 SignPath Foundation，发布者会显示它的名字。
- 一键安装去掉了选程序目录（估计约 600–700 MB 在 C 盘，实测后写进 README），只剩 `/D=`。
- electron-builder 自带的几条 NSIS 报错（卸载旧版失败、解压失败）只有英文。
- 卸载时删除数据是不可撤销的；没有标记的文件夹只删已知条目，列表不全时只会留下文件，不会多删。
- 跟随系统代理可能让 DeepSeek 的流量走一个用户忘了的、或者已经退出的代理；诊断和修复卡会点名代理，可以关掉。
- `NODE_USE_SYSTEM_CA` 在 `ELECTRON_RUN_AS_NODE` 下是否有效未验证；验证不了就不设，使用 TLS 检查的公司网络仍然连不上，只是提示更明确。
- 导入后 Main Bot 提前换段要读一遍最近的对话写交接说明，冷缓存时会花不少 token（#384 实测 17 万 token）。
- 推荐的盘按总线类型排除了 USB、SD 和虚拟盘，但报告成固定盘的移动硬盘仍可能被推荐；PowerShell 被策略禁掉的机器上没有推荐盘，只有「其他位置…」。
- 〔移到…〕之后应用自己建的旧总工作区不在了（改名或逐个搬走），DSH Agent 的 Session 要重新选文件夹；Bot 和群的 Session 换段，不受影响。用户自己挑的总工作区不搬，搬完后它和 `R\workspace` 都在：团队换了文件夹，不是占两份。
- 从 DeepSeek Harness 复制过来的团队在两边各占一份：应用从不写 `~/.dsh`，所以不能替用户删原件，只能把多占的空间写在卡片和设置里。
- 后台复制工作文件在不支持硬链接的文件系统（FAT、exFAT）上退回到「查一次再改名」，查和改名之间 Bot 新建的同名文件会被盖掉。
