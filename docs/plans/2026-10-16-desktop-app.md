# 桌面应用

- 日期：2026-10-16
- 相关：PR #275；[愿景](../vision.zh.md)「两种形态」、[DSH 让步总账](2026-10-13-dsh-concessions.md)

## 为什么

插件版跑在用户自己的 DSH 里，界面结构、全局配置和 DSH 版本都由 DSH 决定，很多地方只能让步（见让步总账）。用户的 DSH 一更新，Bot 也可能被打坏。桌面应用让 DS Bot 自己掌握 profile、数据、界面和 DSH 版本，一打开就是 Bot 团队。

取舍：

- **引擎用 DSH，不另写 Agent 运行时。** Bot 的回合、工具、模型、会话、MCP、技能照旧走 DSH，和插件版一样。
- **界面自己写，不建在 DSH 的网页前端上。** DSH 网页前端启动时要激活全部界面插件，一个插件出错整页停住；它的模块格式和页面结构由 DSH 决定，还在变。Bot 界面要能按页面加载，一个插件出错只影响它自己。代价是 DSH 插件里管界面的那部分不能原样装进来，要小改。

## 已定的行为

### 结构

| 部分 | 做什么 |
|---|---|
| 壳 | Electron 主进程。只开一个实例；窗口用 `dsh-app://app` 加载页面，把请求转发给引擎；管引擎进程的启动和退出。窗口无边框：没有系统标题栏；页面最上面一行可以拖动窗口，最小化、最大化、关闭三个按钮在这一行的最右边（macOS 的红绿灯在最左边） |
| 引擎 | 子进程，用 Electron 自带的 Node 运行。通过 `@deepseek-ai/dsh/profile-boot` 的 `runProfile()` 启动 profile `ds-bot`，只监听 `127.0.0.1` 上系统分配的端口。环境变量 `DS_BOT_APP=1` 告诉 ds-bot 它跑在桌面应用里 |
| 界面 | DS Bot 自己写的网页（React + Vite）。只认 DS Bot 自己的接口：引擎里的 ds-bot 用 HTTP 和事件流提供团队、对话和设置的数据，界面不直接调 DSH 的接口，也不引用 `@deepseek-ai/*` 的包。DSH 只出现在引擎这一层。Bot 界面（侧栏、对话、详情、弹窗和它们的样式）和插件版是同一套代码，两边长得一样；插件版里由 DSH 画的部分（Markdown 排版、会话框架），窗口自己画 |

- 插件版和桌面应用用同一份 `ds-bot`，插件版不变。
- 安装包和 `ds-bot` 用同一个版本号。
- 引擎的 profile 由三个 bundle 叠成：DSH 的 `dsh-base`、桌面应用的引擎层 `deepseek-bot-engine`、`ds-bot`，用户装的插件排在后面。引擎层只放引擎用的东西：给 ds-bot 接口用的本机传输、ds-bot 用到的宿主服务、Bot 会话用的 `standard` 预设（不带目标）。DSH 网页前端的部分一个都不加载。每次启动时，引擎把这三个 bundle 排回最前面。

### 界面

- Bot 详情里显示这个 Bot 当前对话的轮数、输出速度（tok/s）、缓存命中和上下文用量。插件版里这一行在 DSH 输入框下面的状态栏，窗口里没有这个状态栏。

### DSH 版本

- 安装包锁定一个 DSH 版本，只跟 DSH 的 rc 版本，不跟 alpha 版本。现在是 0.2.0-rc.2。
- DSH 的修复和新功能，跟着 DeepSeek Bot 的新版本一起到用户手里。

### 数据

- 数据位置就是桌面应用的 `DSH_HOME`，默认 `~/.ds-bot`。profile、会话、团队数据、模型设置和密钥都在这里。
- 壳自己的数据（窗口、浏览器存储）放在系统给应用的目录里。
- 桌面应用不写用户 DSH 的 `~/.dsh`，导入时只读。

### 首次启动和导入

- 首次启动分别选数据位置和 Bot 工作文件夹，以后能在设置里改。
- 发现用户 DSH 里已有团队时，问要不要导入。导入复制 Bot、群、记忆、会话、附件、模型设置和密钥，旧位置一个字节都不改。导入以后两个团队各走各的，不同步。
- 导入后，每个 Bot 和群在下一个回合前换到新的一段（新工作文件夹），旧段只当历史读，照常能看、能搜。以后搬工作文件夹也一样。
- 用户 DSH 写的会话格式比锁定版新时，停下来请用户先更新 DeepSeek Bot。

### 插件

- DSH 插件的引擎部分（工具、模型、MCP、技能、搜索等）原样安装、原样运行。安装用应用自带的 pnpm。
- 界面插件的写法照 Cordis：插件提供和使用服务、声明依赖、每个注册都能撤销、界面靠插槽组合。
- 和 DSH 重叠的位置，用 DSH 的插槽名和数据：先做工具卡片（`tool.call.toolview`）、全局弹层（`shell.overlay`）和设置（`settings.section`、`settings.general.item`）。DSH 的界面插件换打包方式、接上这些插槽就能迁过来。
- 界面插件按页面加载。一个插件出错，只有它那一块显示错误，其他部分照常。
- 电脑操作和浏览器操作：DSH 的提供方插件和 DS Bot 自己的都能装，用户在设置里选用哪一个，同一时间只加载一个。界面要能显示这些插件用到的截图、审批和提问。

### 安装和更新

- 应用标识（appId）是 `io.github.fei2411.deepseekbot`，以后不改：Windows 靠它认出这个应用和它的更新，macOS 用它当应用标识。
- Windows（x64）：安装向导，可以改程序位置，装完可以直接运行。只给当前用户安装：不问「为所有用户还是只为我」，不要管理员权限，默认装在 `%LOCALAPPDATA%\Programs\DeepSeek Bot`。卸载不删数据位置。
- Windows 自动更新：后台下载，校验 sha512，下载完在窗口里提示重启以更新；不重启的话，下次退出时装上。
- macOS（Apple 芯片和 Intel）：dmg；不能自动更新，有新版时提示下载。
- 安装包带着锁定的 DSH 装上的全部文件，不按 profile 删减。
- 不签名。

## 不做什么

- 不 fork DSH，不给 DSH 打补丁。
- 不把 DSH 的网页前端当作 Bot 界面的底层，也不原样加载 DSH 的界面插件。
- 不做 npm 安装的桌面应用，也不做在 DSH Desktop 里一键安装。
- 第一版不带 Office 技能。

## 暂时不做

以后再看要不要加。插件版里照旧都有。

- DSH 的右侧栏（文件、终端）。
- 设置里的「经典 Agent 模式」（切到 DSH 自己的界面）。

## 已知限制

- 窗口里还没有：群聊的历史消息、工具卡片和审批、首次启动和导入、DeepSeek 账号登录、每个 Bot 的浏览器、更新。侧栏每一行的最新一句只显示打开窗口以后的新消息。插件版里打开 DSH 自己界面的入口（连接插件、管理模型、Harness 设置，「+」里的添加文件和引用对话）窗口里也没有。模型和密钥目前用环境变量，或数据位置里的 `.env`、`.credentials.yaml` 设置。
- 不签名：Windows 第一次运行会弹出 SmartScreen 警告，macOS 要在系统设置里手动放行。
- 会话里记着工作文件夹的完整路径，不能改。所以导入和搬工作文件夹都要换段。
- 安装的 `@deepseek-ai/dsh` 包带着 DSH 的网页前端、Office 套件和语音包，所以安装包里仍有这些文件，只是不加载。
